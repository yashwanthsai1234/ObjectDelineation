# Phase 2 GPU sessions: V0 and V1

Phase 2 (SFT) uses rented GPUs on Vast.ai in two sessions. **V0** is a 10-minute safety test with no job. **V1** is
the real session: it trains and tests the models. This note explains both, with the code that runs them. Plan:
[PLAN.md](PLAN.md) §3.3, §4.7, §4.9, §5.1, §6.1. Text in the "STE" blocks follows ASD-STE100 rules (short sentences,
active voice, one instruction per sentence).

```
 Phase 0 ✅ census ─ Phase 1 ✅ reward + data ─ Phase 2 👉 SFT ─ Phase 3/4 GRPO ─ 5 controller ─ 6 Track C ─ 7 3D ─ 8 CUDA ─ 9 release
                                                   │
                     Stage 0 plan ✅ ─ Stage 1 Mac build ✅ ─ Stage 2 V0 ✅ ─ Stage 3 V1 ─ Stage 4 review ─ Stage 5 exit
```

## Part 1. The story

You rent a car by the hour from strangers.

- The rental company is **Vast**. The cars are **GPU boxes**. The meter runs until you **destroy** (return) the car.
  A stopped car still costs money for its disk, so we never stop a box: we destroy it.
- The danger: **you forget the car**. The laptop sleeps, Wi-Fi drops, a script crashes, and the meter runs all night.

| Character | In the story | In the code |
|---|---|---|
| The assistant | Finds a car, checks the price, rents it, carries the luggage, brings results home, returns the car, writes every action in a receipt book | `vast/policy.py` (Mac) |
| The alarm clock inside the car | Returns the car by itself when the time is over, even if the assistant sleeps | `vast/watchdog.sh` (box) |
| The night guard | Walks around every hour and returns any car that should not be out | `sweep_orphans.sh` (launchd, hourly) |
| The receipt book | Every rent, return and dollar | `vast/ledger.csv` |
| The locked garage | Holds the toolbox (Linux, Python, torch, vLLM) that the car fetches with a read-only key | GHCR image `objdel-gpu` |

**V0** was a test drive with an empty car: rent the cheapest safe car, set the alarm clock to 10 minutes, watch it
return itself. **V1** is the real trip: a small student model goes to school (SFT) on a 4090, takes its exams (gates),
and we bring the report cards home.

> **STE.** `terms()` lists each condition that a box must meet. `query()` sends the conditions to Vast. `reasons()`
> checks each returned offer again on the Mac. If one condition fails, the tool rejects the offer.

#### `policy.py` section 3: memory (`ledger`, `active`, `accrued`, `spend`)

```python
def ledger(**row):
    if any(SECRET_RE.search(str(v)) for v in row.values()):   # "ghp_", "Bearer ", "PRIVATE KEY" …
        raise ValueError("refusing to write a secret-looking value to the ledger")

def accrued(r, t):          # cost of one run from its start to t
    h = max(0.0, t - r["started"]) / 3600
    return r["dph"] * h + r["inet_down_cost"] * DOWN_GB + r["inet_up_cost"] * UP_GB_PER_H * h
```

> **STE.** `ledger()` adds one line for each event. It refuses values that look like keys. `spend()` adds the closed
> costs and the costs of live boxes.

#### `policy.py` section 4: messengers (`secret`, `vast`, `remote`, `rsync`)

```python
def vast(*args, tries=1):
    env["VAST_API_KEY"] = secret("objdel-vast-scoped")             # macOS keychain, never a file
    p = subprocess.run(["vastai", *args], capture_output=True, text=True, env=env)
    if not p.returncode and (p.stdout.strip() or "--raw" not in args):   # V0: errors exit 0 with no output
        return json.loads(p.stdout) if "--raw" in args else p.stdout
    die(f"vastai {args[:2]} failed: {p.stderr.strip()[-300:]}")
```

#### `policy.py` section 5: the commands

**`launch`**: rent safely. Each box is a check; a failed check stops the launch.

```
                    launch.sh <offer> <run_id> --cap-hours H
                                     │
              run_id valid, not in use? ── no ──► STOP
              offer picked, still passes the filter? ── no ──► STOP
              spent + worst case of this box > $15? ── yes ─► STOP (hard stop)
              ≥ $10 without --owner-approved? ── yes ─► STOP (alarm)
              another box on? ── yes ─► STOP (one at a time)
                                     │
              create: allowlisted image, read-only GHCR token, watchdog packed into --onstart-cmd
                                     │
              every 10 s: running + IP + SSH port? ── failed / 15 min ──► DESTROY, STOP
                                     │                Ctrl-C at any time ──► DESTROY
                          print "running: ssh -p … root@…"
```

```python
b64 = base64.b64encode((HERE / "watchdog.sh").read_bytes()).decode()      # onstart_cmd(): no secret inside
return f"printf %s {b64} | base64 -d > /root/watchdog.sh && RUN_ID=… WATCHDOG_CAP_S={cap_s} … nohup bash /root/watchdog.sh …"
```

**`sync_up`**: carry the luggage. Only git-tracked code (no `data/`, `docs/`, lab results); `pip install -e .` and an
import test on the box; the LIDC bundle checked with SHA-256 twice. RIGA is refused without written permission.

```
 git ls-files ─filter─► code list ──rsync──► /workspace/src ──► pip install -e . ──► import test
 build/bundles/bundle-lidc.tar ──rsync──► /workspace/data ──► sha256sum -c ──► untar ──► sha256sum -c
```

**`run`**: start a job in `tmux` with `timeout` ending 10 min before the box's cap; writes `HEARTBEAT` every 60 s and
`EXIT` with the exit code.

**`pull` / `teardown`**: touch `PULLED_OK.next` on the box, rsync `runs/<id>/` home with checksums (without the full
checkpoints in `rolling/ decay/ stable/`), then rename it to `PULLED_OK`, so the marker keeps the pull's start time;
teardown = final pull (3 tries), then always destroy, verify absent, save invoice, ledger.

**`push_hf`** (after the last pull, before teardown): the selected branch of a config's run to the private HF repo
`svenk029/objdel-sft`, repo branch = the run's `output_dir` (e.g. `r1-lfm`), with the base LICENSE and a model card.
The keychain token (`objdel-hf-write`) must be fine-grained with write on that one repo only, or the Mac refuses
before touching the box; it reaches the box only as the ssh session's stdin. The box refuses a public repo, a run
with no selected branch and anything not trained on LIDC (RIGA: no redistribution).

**`sweep_orphans`**: the night guard. Closes runs whose box is gone, destroys unknown or overdue boxes, destroys every
box at $15, and shows a macOS notification for each action.

#### `watchdog.sh`: the alarm clock

```bash
destroy() {
    until curl -fsS -X DELETE -H "Authorization: Bearer ${CONTAINER_API_KEY}" "$API/instances/${CONTAINER_ID}/"; do
        sleep 10
    done
}
while :; do
    if (( $(date +%s) - start >= CAP_S )); then destroy "cap ${CAP_S} s reached"; fi
    util=$(nvidia-smi --query-gpu=utilization.gpu --format=csv,noheader,nounits | sort -n | tail -1)
    [[ $util =~ ^[0-9]+$ ]] || util=100        # no reading = busy; the cap still protects
    …idle rule: GPU < 5 % for 30 min AND job EXITed AND results pulled → destroy…
    sleep 60
done
```

```
        box starts → save start time
                      ▼
  ┌──► time since start ≥ cap? ── yes ──► DELETE box (retry every 10 s)
  │                   │ no                         ▲
  │      GPU use < 5 %? ── no → reset idle         │ yes
  │                   │ yes                        │
  │      idle ≥ 30 min AND EXIT AND PULLED_OK newer than every result? ─┘
  │                   │ no
  └──── sleep 60 s ◄──┘
```

> **STE.** The watchdog is the only program of ours that runs on the box. It checks the time every 60 seconds. At the
> time limit, it destroys the box. It uses `CONTAINER_API_KEY`, which Vast gives to the box. If the request fails, it
> tries again every 10 seconds.
>
> **WARNING:** The watchdog is the only protection when the Mac is off. Do not start a box without a time cap.

## Part 4. V1: the real session (built, not yet run)

### 4.1 What V1 answers

- **C1, smallest viable model:** which is the smallest model that learns to write legal polygons? Ladder:
  **LFM2.5-VL-450M** → Qwen3.5-0.8B → Qwen3-VL-2B (owner approval). Stop at the first that passes.
- **C2, holes:** does a model taught with holes (A0′) find holes that a model taught without holes (A0) cannot?

### 4.2 The six runs on one RTX 4090

```
  R0  CHECK THE BOX + MEASURE SPEED          ~0.9 h   image_check, x86 hashes, reward speed, parity, timing, Qwen3.5 arm
   │      stop rule: projected R1 > 2× the plan's high estimate → stop and re-plan
  R1  TRAIN LFM (SFT) + EXAMS              0.8–1.7 h  train_sft → select_ckpt (+ sample_vllm) → gates
   │      gates fail → one diagnostic run (R-diag) → next rung
  R2  G-PROBE: 20 GRPO steps               0.2–0.5 h  can RL improve this checkpoint?
   │      C1 = this rung. STOP the ladder.
  R3  A0′ seed 2  ┐
  R4  A0′ seed 3  ├ C2                     1.6–4.2 h  topology probe → hole recall, 3-seed rule
  R5  A0  seed 1  ┘
   │
  teardown: final pull, destroy, invoice                  total 3.9–7.7 GPU-h, ≈ $2.5–5 at $0.66/h
```

> **STE.** R0 makes sure that the box is correct. R0 also measures the real time per training step. If R1 will take
> more than two times the planned time, stop. R1 trains the model and tests it. R2 does a short reinforcement-learning
> test. R3 to R5 train three more models to compare "holes" with "no holes".

### 4.5 The exams (gates, PLAN §5.1)

| Gate | Question | Pass mark |
|---|---|---|
| G-format | Can we read the answer as a polygon? | parse ≥ 98 %, legal ≥ 90 % |
| G-geometry | Does it cover the nodule? | median IoU_tc ≥ 0.60 on shifted and rescaled crops |
| G-prior | Better than a guess that ignores the image? | paired CI lower bound > 0 |
| G-precision | Small objects (6–16 px)? | legal ≥ 95 %, ASSD ≤ 0.6 px, IoU ≥ 0.80 |
| G-topology | No false holes on simple shapes? | gate on simple controls; hole recall reported |
| G-signal | Are the 8 answers different enough for RL? | duplicates ≤ 10 %, σ-share ≥ 50 % |
| G-vision | Does it still look at the image? | not collapsed vs the base model |
| G-probe | Do 20 GRPO steps improve it? | rise above the step-0 noise floor |
| G-cost | What will Phase 3 cost? | projection ≤ $150 |

counter (code lines = no blank, comment or docstring lines) over the eleven V1 programs:

| Files | Lines | Code lines |
|---|---|---|

What made it shorter: one argparse table in `policy.py`; one `load()` for three JSON readers; `sh()` stops on failure
(the ssh and rsync helpers lost their copies); one `score_items` for `select_ckpt` and `g_probe`; one `preload()` for
three G-vision loaders in `train_sft`; test helpers instead of one-item-per-line literals. The runner's 30 dry-run
outputs, `--help` texts, the bundle tar hash and the run chains are byte-identical before and after.

> **STE.** 4× was not possible. The code was already dense. Most lines that remain are safety rules (money caps,

> read. To remove them would change what the programs do.
