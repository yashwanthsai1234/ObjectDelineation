## Design choices with evidence

**WSD branches (D5).** Options tried on a tiny Llama (scratchpad `R/wsd_exp.py`, then as a test):
(A) one uninterrupted WSD run per branch (warmup, stable to b, decay d) – the reference;
(B) one stable run that saves a full checkpoint at each b, then per branch a new trainer resumed from it with the
same `warmup_stable_decay` schedule ending at b + d. Result: B's weights equal A's **bit for bit** (max |Δ| = 0) and
the LR traces are identical, including the length-grouped data order (HF resume restores optimizer, scheduler, RNG
and skips the consumed batches). A costs 3.5 stable epochs + decays for three depths, B costs 2 + decays (D5's 2.5
epoch-equivalents). An in-process branching callback (snapshot model + optimizer at b, replay later) would
re-implement what resume already does, so B was picked. Test: `test_wsd_resumed_decay_equals_uninterrupted_run`.
The schedule itself is T's `configs.sft_config(model, out, steps, branch_at)`; `train_sft.plan` mirrors it
(test checks `max_steps` and `warmup_steps` against sft_config).

**Epoch order.** HF's group_by_length sampler shuffles the whole dataset, which would mix view epochs (a 1-epoch
branch would see ~25 % of items zero times). `train_sft` overrides `_get_train_sampler`: view epoch e in order,
length-grouped inside each epoch with a generator seeded by `data_seed + e` (deterministic, so resume is exact).
The epoch comes from V's `row_id` (`"<epoch>/<item>/<rater>/<rep>"`). A branch's decay continues the stream, so
the view needs epochs beyond max(b): train_sft raises before training when it does not (R1 view: `--epochs 3`).

**Checkpoints.** `save_strategy="no"` plus a callback that sets `should_save` every `rolling_minutes` and at each
branch point; HF rotation keeps 3 rolling checkpoints; branch-point checkpoints are copied to `stable/e<b>` in
`on_save`. After the decays: `branches/e<b>` and `stable/e<b>` are model-only with the processor saved (sampler
input), rolling/decay dirs deleted. Manifest: config, view hash + manifest SHA-256, SHA-256 over `src/objdel/**.py`
+ the script, git HEAD, step plan, G-vision log, pid, status (`running` / `done` / `aborted`), exit code 3 on abort.

**G-vision in training (D7).** `vision_check` = E's `fixed_set` + `check(reference=R0 value)` under no_grad (train
mode restored after; `check` leaves the model in eval). `record_vision` logs every result and stops only on E's
`decide` action "abort" (ratio < 0.5 and TV < 0.002), with the reason in the manifest.

**select_ckpt (D12/D13).** Refuses unless the manifest says `done` and the pid is gone; preloads every scored root
(shifted, rescaled) then `serve.fork_pool`; imports the scorer (`objdel.eval.metrics`) at module level, because on
macOS a forked worker that imports a module after the parent started threads dies in objc (BrokenProcessPool in
the first smoke; fixed by importing before the fork). Per branch: `export_prompts(processor=branch's,
stop_ids=rewards.stop_ids)` → sampler child (vLLM command or `hf-sample`, the same JSONL contract) after
`cuda_untouched()` → `import_completions` → `metrics(caches=CacheRef(id, root))` on the pool → `summarize`,
`signal.group/panel`; G-vision on the CPU in fp32. Eligibility = prereg.RB["eligible"]; `prereg.select_rb` picks.
Gates on the selected branch (the deepest when none is eligible, §6.3): views shifted (+ rescaled), G-prior (b)
from `baselines.fit_prior/score_prior` (paired per item, `signal.ci` nodule bootstrap), probes (precision,
topology) when `--probes` is given → `gates.phase2_entry` → `gates.json`, `report.json`, `selected.json` (records
`cuda_initialized`, asserted False in the smoke).

**g_probe (§5.1).** prereg.G_PROBE LR (5e-6 / 5e-5 LoRA), constant, 20 steps, `use_vllm=False`, sampling fields
from `configs.sampling` mapped to GRPOConfig names (presence / frequency asserted 0). Probe set = first 128 rows of
the shifted view; step-0 drawn twice (seeds 11, 12), step 20 once (13) through `sample.sample`; per-item raw R via
`signal.per_item`; `prereg.g_probe` verdict; Spearman of step-0 sd_geom / r_std / mixed vs gain; timing split.

**Data roots.** Configs hold paths relative to `data_root` (default `data`; Vast: `--data_root
/workspace/data/lidc`, agent O's layout).
