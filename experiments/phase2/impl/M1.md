# M1 implementation note

LANDED: frame/augment API (2026-10-20). Code against this; build scripts and real-data evidence follow below.

## API as built (C-VIEW)

- `objdel.targets.frame(item, cfg=None, *, offset=(0, 0), side=None, window=None) -> Frame`. Defaults are byte
  identical to Phase 1. `offset` moves the window in item pixels from where the policy centres a window of side S;
  `side` forces S (a divisor of 1000 in [min_side, max_side], scale 1). A moved or resized window must hold the
  rater union with `CLEARANCE = 2` px and meet no `meta["other_nodules"]` box, else `ValueError`. `window=(lo, hi)`:
  HU window for LIDC (default `LUNG_WINDOW = (-1000, 400)`); ignored for RIGA.
  Helpers in `objdel.targets.frame`: `union_box`, `centred(item, side)`, `crowded(item, box)`, `hu_window(a, window)`,
  `upscale(img, side)`.
- `objdel.targets.augment`: `OPS = ("id", "r90", "r180", "r270", "fh", "fv", "tr", "at")`, `DATASET_OPS`
  (`riga: ("id", "fh")`), `INVERSE`, `apply(a, op)` (last two axes), `render(spec, context) -> uint8 (s, s, 3)`
  (s = 512 for LIDC, S for RIGA), `load_context(view_dir, item_id) -> {"pixels", "x0", "y0", "shape"}`,
  `draw(item, rng, side=None)`, `neighbour_side`, `jitter(rng)`, `row_rng(*keys)`.
- Training view row (`data/views/<view>/rows.jsonl`, one JSON object per line, sorted by
  (epoch, item_id, rater_index, rep)):
  `{"row_id": "<epoch>/<item_id>/<rater_index>/<rep>", "epoch", "item_id", "dataset", "rater", "rater_index", "op",
  "offset": [dx, dy], "side": S, "box": [x0, y0, x1, y1], "window": [lo, hi] | null, "noise_sigma", "noise_seed",
  "simple": bool, "rep", "target"}`. `box` (the absolute window in item pixels) is an extension of the contract:
  `render` reads it with `side`, `op`, `window`, `noise_*` and `dataset`. Image for a row:
  `augment.render(row, augment.load_context(view_dir, row["item_id"]))`.
- Eval views (`data/eval_views/<ds>-<split>-{shifted,rescaled}/`): the `data/prepared` layout written by
  `objdel.train.dataset._prepare` (PNG, targets, `ExpertCache.build` caches) plus `"view": {"offset", "side",
  "kept_side", "fallback"}`; `manifest.json` has `files[rel].sha256` (so `cache_loader` and `serve.preload` accept
  it), `sets[...]` as prepare plus `kept_side`, `fallback`, `side` counts.
- M9 (`experiments/phase1/fetch_lidc_pixels.py`, I45): `z_keys(keep)` raises when two kept DICOMs share a
  `z<mm:.2f>` key (was: silent overwrite); `hounsfield(pixels, slope, intercept)` raises on non-integral HU or HU
  outside int16 (was: truncating, wrapping `astype(np.int16)`). Both make the series report FAILED.

## Design choices (evidence)

- **Crop before trace** (`build._rings`): B3 P4's version promoted. Re-run on real data with the src code: all four
  prepared target-set hashes reproduced (riga train 3,282 / val 348, lidc train 23,469 / val 3,444, `True` each;
  84 + 9 + 38 + 5 s with 2 procs); `data` test rebuilds both val sets on every run.
- **Row `box` extension** vs recomputing the centred window in `render` from the union: storing the box keeps
  `render` free of masks (the context npz has no masks) and is 1 field; recomputing would need the union box in the
  npz. Chosen: `box`.
- **Context crop extent**: the union of all admissible windows of the largest side the scale draw can give, plus the
  policy window, clipped to the image (no dependence on the drawn rows, so more epochs never invalidate contexts).
  `render` refuses a window that leaves the context (test). LIDC train: 7,341 files, 209.6 MB (29 KB/item; replaces
  the plan's 0.3–0.5 GB estimate).
- **npz writer**: `np.savez_compressed` stamps the wall-clock time into the zip, so two builds differ; a 6-line
  writer with a fixed `ZipInfo` date makes builds byte-identical (verified: full LIDC build with 2 procs vs 1 proc,
  `diff -r` identical apart from `build_report.json`).
- **Noise** drawn at frame resolution (S x S, `row_rng("noise", noise_seed)`, rounded to integer HU) and added
  before windowing; padding outside the image stays black as in `frame`. Offline reference in the tests adds the
  same noise to the full HU image and calls `frame`; equal on every sampled row (synthetic and real).
- **Draws**: per row `row_rng(seed, epoch, item_id, rater_index, rep)` (SHA-256 seeded), order and subset
  independent; shift by rejection sampling (uniform over the admissible, non-crowded set). Voting raters from
  `reward.voters` on the policy frame's signatures (same rule as `ExpertCache`); simple = every object `(0,)`.
  Non-simple LIDC train targets: 414 → 1,656 rows (×4), matching the plan's 414.

  RIGA views get D4-hflip and the window draws only. No RIGA views were built (D16).
- The per-variant token-budget filter (I5) is applied in `dataset.view_rows` (T), not at build time.
- `build_eval_views` calls the private `objdel.train.dataset._prepare(job)`; its job tuple must stay stable (T owns it).
- The overall `1af819f4…` hash includes items without pixels (data/targets); I checked the four per-split prepared
  hashes instead (which are its image-bearing subsets).
- Files are not `ruff format`-ed (the repo's own files are not either; `make lint` = `ruff check` passes).
