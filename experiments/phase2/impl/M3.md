## API as built (C-SERVE, extended)

- `serve.STORE`: `{resolved root: {item key: {object: ExpertCache}}}`.
- `preload(root, datasets, threads=4) -> int` (items loaded): every `<ds>/*.jsonl` under a prepared root
  (data/prepared or an eval view, same layout). Checks each records file's SHA-256 against `manifest.json`
  `files[<ds>/<split>.jsonl].sha256`, then each cache against its record's digest (`ExpertCache.load`).
  ValueError on a dataset with no records, a records file not the manifest's, a cache not its record's.
  LIDC-only opens no RIGA file (test).
- `CacheRef(key, root=None)`: read-only Mapping through STORE; pickles as `(key, root)` (~94 B per job). With
  `root=None` the key must be in exactly one preloaded root (KeyError otherwise).
- `ref_loader(key)` (contract), `loader(root)` (extension: eval views reuse the prepared item ids with other
  caches, so select_ckpt, which preloads several roots before one fork, needs root-bound loaders).
- `fork_pool(n)`: RuntimeError if `torch` is imported and `torch.cuda.is_initialized()`; `gc.freeze()`;
  `ProcessPoolExecutor(n, mp_context=fork, initializer=cv2.setNumThreads, initargs=(0,))`; n `os.getpid`
  warm-up tasks (fork context launches every worker at the first submit, never respawns). Workers see STORE as
  it was at the fork.
- `TRLReward(caches=serve.ref_loader, stop_ids, pool=pool)`: **no code change needed**; `TRLReward` already
  takes `pool` and `score_batch` already makes one `pool.map` per call in chunks of G. Only its docstring
  now points at serve.

## Design choices and evidence (Mac M3, quiet: load 3.3–4.9)

| Choice | Options measured | Result | Picked |
|---|---|---|---|
| Preload threads | 1 / 2 / 4 on all LIDC (8,425 items, train + val) | 4.3 / 3.8 / 4.7–4.9 s (small files, GIL-bound: no gain) | 4 |
| | 1 / 2 / 4 on 40 RIGA items (big zlib npz, GIL released) | 1.10–1.16 / 0.58 / 0.33–0.37 s (3.2×) | (same) |
| Job payload | 32 ExpertCache dicts vs 32 CacheRef (LIDC) | 450,039 B vs 3,017 B | CacheRef |
| Store key | item id only (lab) vs per root | eval views reuse item ids with different caches: a flat store collides | per root |
| Start method | fork vs forkserver (B4 §2 robustness 4) | forkserver re-imports the TRL script's torch (macOS crash 3/3, Linux 49.7 s start) | fork only; forkserver, `serve_preload`, mem/CPU probes dropped |
| Records source | glob + manifest SHA vs manifest `sets` | glob works for eval views whose manifest may lack `sets`; SHA from `files` | glob + `files` SHA |

Preload of all LIDC caches is 4–5 s on a quiet Mac (B4 measured 30 s at load 23). RIGA at 4 threads projects to
~4.6 s for 547 items (not run: 3.35 GB exceeds this agent's memory budget).
