## API as built

- `objdel.train.dataset.view_rows(view_dir, tokenizer=None, max_tokens=None, a0=False) -> Dataset` (C-ROWS).
  - Columns: `messages` (same as `sft_rows`), `image` (PIL, rendered on access by `augment.render(row, augment.load_context(view_dir, item_id))`), `key`, `rater`, `row_id`, `length`.
  - `length` is the target's token count with a tokenizer, else its character count. `max_tokens` drops answers with tokens + 1 > budget (I5).
  - `a0` parses each target, empties every `holes` list, then canonicalizes and serializes it back.
  - `rows.jsonl` must hash to the manifest's `view_hash`, else ValueError.
  - The rows are V's rows unchanged: voting raters only, non-simple rows repeated.
- `dataset.cache_loader(root, maxsize=64)` reads `manifest.json["files"]` and checks each file's SHA-256 (I45: no glob).
  - `maxsize=None` preloads every cache up front.
  - `prepare` raises OSError when `cv2.imwrite` returns False.
- `configs` additions:
  - `MODELS["qwen3.5-0.8b"]`; `MAX_COMPLETION` is 1,024 for LFM and Qwen3.5.
  - `DTYPE` (Qwen3.5 `bfloat16`, others `float32`, for `from_pretrained(dtype=)`).
  - `TEMPLATES` and `training_template(model, processor)`: raises unless TRL's swap gives `qwen3_5_nothink_training`.
  - `VISION` (B1's regex); `lora(model, force=False)`: r16, all-linear, `exclude_modules=VISION`.
  - `param_groups(model, base_lr)`: two groups, the LM at base_lr and VISION at 0.1×; frozen parameters are left out.
  - `sampling(model)`: vLLM field names, every field explicit, plus `max_tokens`.
  - `sft_config(model, out, steps=None, branch_at=None, **o)`:
    - schedule: `warmup_stable_decay`, warmup round(0.03·steps), linear decay over round(0.15·s) to 0 for a branch at s, `max_steps = s + decay`. The stable phase is the remainder, so up to s the branch schedule is identical to the stable run's (tested).
    - loader: `group_by_length` on `length`, 6 persistent workers, prefetch 2.
    - `gradient_checkpointing` only for Qwen3-VL-2B; `data_seed=0`.
- `objdel.train.sample.export_prompts(rows, path, model, dataset, n, processor=None, stop_ids=None, seed=0)`.
  - Writes `{"id", "prompt", "image", "processor_kwargs", "sampling", "n"}`; `sampling` is `configs.sampling` plus seed and stop_token_ids.
  - It reads image paths from a Dataset's Image column (`decode=False`) and refuses duplicate keys.
  - `import_completions(path, stop_ids)` returns `{"item_id", "samples", "truncated", "tokens"}`. `truncated` is `rewards.truncated`; `tokens` was added at E's request.
- `experiments/phase2/sample_vllm.py --prompts --model --out [--dtype --gpu-memory-utilization 0.85 --max-model-len 2048 --seed --logprobs]`.
  - Imports only the standard library at module level; torch, vllm and PIL are imported inside `main`.
  - `check_memory` exits when less than 90 % of memory is free.
  - `requests` builds the SamplingParams only from the exported fields. `<out>.meta.json` echoes every SamplingParams repr.

## Design choices and evidence

**Lazy render.** Three directions were tried in the sandbox.
- **`datasets.Dataset.with_transform`.** TRL 1.16 SFTTrainer accepts it: it decides on the vision path with `"image" in next(iter(ds))`, skips preparation for vision datasets, and builds `DataCollatorForVisionLanguageModeling`.
  - The problem: transformers' `group_by_length` sampler reads `ds["length"]`, and on a transformed dataset that column is a lazy `Column` whose iteration runs the transform on every row.
  - Measured: **1,005 renders for 1,000 rows** at sampler construction. They run single-threaded in the main process and repeat every epoch, because `get_length_grouped_indices` indexes `lengths[i]`.
- **Plain torch `Dataset`.** Rejected: `_get_train_sampler` only passes `lengths` for a `datasets.Dataset`. Otherwise `LengthGroupedSampler` needs `input_ids` in every item, so it raises (or would have to render every row).
- **TRL collator hook (render in `data_collator`).** Rejected: the rows would need a fake `image` key to get the vision collator. R would then have to rebuild TRL's collator by hand (training chat template, assistant-only flags), and the contract's PIL `image` column would be lost.
- **Chosen: `_ViewRows(Dataset)` + `with_transform(_Render(view_dir))`.** A column read by name (`ds["length"]`) bypasses the transform; integer and batched access (`__getitems__`, the DataLoader path) renders.
  - Sampler: **0 renders**.
  - Per row: 1.5 ms with a mimic render (npz load 0.12 ms, render 1.2 ms).
  - Pickling keeps the subclass, which spawn-started workers need.
  - With V's real `augment.render` (`bench_syn.py`: V's builder on the conftest items, 4 epochs, 24 rows): **1.67 ms per row** (LIDC, 512 px); `length` plus the sampler take 3.5 ms. On a 25k-row table the length column reads in 0.3 ms.
  - A real-store bench was not run. The first attempt hung because my script lacked a `__main__` guard for V's spawn Pool, so this is my mistake, not V's.
  - Tests check the sampler with zero renders, `next(iter(ds))` containing `image`, and pickling.

**LoRA LM-only.** Linear-module name lists for all four models were recorded offline, from `AutoModelForImageTextToText.from_config` on the meta device with the cached configs. The test builds a toy module tree with those names and runs PEFT's real `inject_adapter_in_model`: no vision or projector module is adapted, and every LM linear layer is. The same lists feed the param-group test. Phase 1 test changed accordingly: `test_lora_only_where_the_plan_needs_it` now also asserts `exclude_modules`.

**Qwen3.5 template.** `training_template` on the cached `Qwen/Qwen3.5-0.8B` processor resolves to `qwen3_5_nothink_training` (offline run).

**Bridge texts.** The real cached processors reproduce B5's `prompts.json` texts in **192 / 192** cases (3 models × 2 datasets × 32). B5 showed those texts give vLLM prompt ids equal to the training env's.
- B5's vLLM CPU outputs end `token_ids` with the stop id when `finish_reason == "stop"` (LFM 7, SmolVLM 49279), so `rewards.truncated` applies unchanged.

**Phase 1 tests changed (plan behaviour):**
- `test_train_configs.py`: MODELS now includes Qwen3.5; Qwen3.5's budget is 1,024; LoRA excludes the vision tower and projector.
