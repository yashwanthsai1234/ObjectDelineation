# BK3 break-it findings

Agent BK3 (wave 2): the runner pipeline `train_sft` → `select_ckpt` → `g_probe`, `configs/*.yaml`,
`objdel.train.configs`, `objdel.eval.vision`. Tests: `tests/test_p2_breakit_runners.py`. 43 pass (guards), 13 strict
xfails, 3 of the 43 slow; about 16 s on the CPU with a tiny random LFM2-VL. Known S1-* issues are not repeated here.

Severity: **high** means a planned Vast run would crash, waste GPU time, or pick the wrong checkpoint.

Guards that hold: all 14 YAMLs reject unknown keys (TrlParser), use LR 5e-5 with no LoRA, max completion 1,024
(LFM / Qwen3.5) and effective batch 32. G_PROBE LRs are 5e-6 / 5e-5 (20 steps). For odd epoch sizes (7, 13, 22, 731,
733 steps), the plan's warmup is 3 % ± 0.5 and decay 15 % ± 0.5. The deepest decay fits in a 3-epoch view and exceeds
2 epochs (S1-8). `param_groups` covers every parameter exactly once on full-size meta-device LFM2.5-VL-450M,
Qwen3.5-0.8B and Qwen3-VL-2B, and its 0.1× group is exactly the tower and projector. The sampling fields reach
GRPOConfig and hf-sample's `generate` with D13's values. With every branch ineligible, the deepest is gated; an empty
branch list writes `selected.json` with no pick. A failing sampler child stops select_ckpt. The step-0 null with zero
variance gives h0 = 0 and sane verdicts. Two in-process smoke runs give bit-identical branches. The rolling rotation
never holds more than 3 checkpoints. A G-vision abort stops at the step where it fires: warn alone does not stop it,
the reason is in the manifest, exit code is 3, there are no branches, and the stable checkpoints are model-only.
The "missing `lm_head.weight`" warning on resume is benign: both models tie their embeddings.

## Simplicity audit (train_sft 256 / select_ckpt 311 / g_probe 153 lines)

- **`select_ckpt.py:58-83` `sampler_cmd`: 26 lines → 5.** Use one shared tail `["--prompts", p, "--model", m,
  "--out", o]` and pick the head with a conditional expression. The current length comes from ruff's
  one-element-per-line formatting.
- **`select_ckpt.py:255-307` `hf_sample`: 53 lines.** Move it to `objdel.train.sample.hf_generate_jsonl` (unit-testable
  and covered by `make cov`) or to `experiments/phase2/sample_hf.py`. The JSON write at lines 295-306 is 3 lines when
  not exploded. Saves about 50 lines here.
- **`select_ckpt.py:96-106` `eligible`.** Move it to `prereg` beside `RB`, since prereg holds "every pre-registered
  rule as data + pure functions". `select_ckpt.py:146-156` `prior_ci` is a pure statistic and belongs in
  `objdel.eval.signal`. That is about 20 lines out of the runner.
- **`select_ckpt.py:138` and `g_probe.py:38-49` build the same `_score` job tuples.** Use one helper,
  `select_ckpt.jobs(done, meta, root)`, to save about 10 lines.
- **`g_probe.py:90-108`.** Lines 90-92 are the sampling-name mapping (S1-10): use `configs.grpo_sampling(model)`.
  `lr_scheduler_type="constant"` and `warmup_steps=0` repeat `grpo_config` defaults (`configs.py:167`). About 6 lines
  saved.
- **`train_sft.py:221-222`.** A throwaway `SFTConfig` is built only to read the batch sizes; compute
  `per_device * gas` from `args.sft` instead. Lines 205-209 (`freeze_vision`) become `lm, vis = groups; groups = [lm]`
  plus a `requires_grad_(False)` loop over `vis["params"]`. Lines 241-247 strip optimizer files with a name
  heuristic; deleting `stable/<b>`'s optimizer, scheduler and RNG files right after its branch finishes frees disk
  earlier and makes the end-of-run loop unnecessary. About 10 lines saved.
- **`train_sft.py:100-114` `sha256` / `write_json`.** These duplicate `objdel.data.store._sha256` and
  `build_views.py:128`. One `objdel` util would serve all of them.
- **Net:** about 100 lines (select_ckpt ≈ 230, g_probe ≈ 135, train_sft ≈ 240) with no behaviour change.
