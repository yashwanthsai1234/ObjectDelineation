- `splits.near_duplicates` on 120 random descriptors at thresholds 0.45, −inf and 0.05: identical pair lists.

The data layer was already small: one implementation per operation, and vulture (installed in scratch, confidence 0)
found only one unused name (`SERIES` in the break-it tests). The "two near-duplicate detectors" are both needed. K11

speculative parameters, stale text and duplicated tests.

## Changes and why

**`riga.py`**
- New `components(o, min_size)` gives the 8-connected labels plus a size-keep table. It replaces three copies of
  label → bincount → `keep[0] = False` (in `ink`, `drawing` and `crop_box`).
- Removed the `if not n: return …` early exits in `ink`, `drawing` and `crop_box`. With no component, `keep[lab]` is
  already all False, and `crop_box` already falls back to the full frame (checked by the differential run).
- `crop_box` returns early instead of mutating four defaults. `extract` unpacks the stage-A box once and writes disc
  and cup in one assignment.
- `keypoints(ref, n=500, width=800, inset=20)` → `keypoints(ref)` with the constants `ORB_FEATURES, ORB_WIDTH,
  FIELD_INSET`. No caller ever passed the options. They were calibrated together with `splits.ORB_DUP`, so they are
  constants, not knobs.
- Docstring: the B3-1 paragraph is shorter and keeps the measured numbers. The first line now names both
  near-duplicate features. The stale scikit-image link (`main/skimage/filters/thresholding.py` is now 404, because
  the code moved to `src/skimage` and `_skimage2`) is pinned to `v0.25.2`. There I re-read the implementation:
  `low` is clipped to `high`, both tests are strict `>`, and `ndi.label` uses its default 4-connectivity. So
  `riga.hysteresis` still matches for `low <= high`, the range the Hypothesis test draws. I kept `seeded[0] = False`:
  it only matters for `low > high`, and without it the background would turn True there.

**`lidc.py`**
- New `_series(root)` and `_messages(xml_root)`. `series_files` and `sop_z` each had their own "rglob, parse, skip
  non-LIDC messages, read the series uid" loop, and `parse` repeated the uid lookup. Six lines longer in total, but
  the XML walk now exists once.

**`store.py`**
- Stale citation: the module said HF `datasets` uses 100-row row groups for image data
  (`PARQUET_ROW_GROUP_SIZE_FOR_IMAGE_DATASETS`). In `datasets` 5.x (installed 5.1.0) that constant is `None`, and
  row groups close at `MAX_ROW_GROUP_SIZE = "100MB"` of uncompressed data, which is what `ROW_GROUP_BYTES = 128 MB`
  already does. Text corrected. The `Item` docstring said `image=None` only for missing CT; it also covers the
  BinRushed1 reconstruction (B3-1). No code change.

**`splits.py`**
- `near_duplicates(descriptors, threshold, shift, chunk)` → `near_duplicates(descriptors, threshold)`. `shift` and
  `chunk` were never passed. The shift window `near` is now built once, outside the batch loop.
- Broken citation: `https://arxiv.org/abs/2006.01030` was cited as FIRE, but it is "GoodPoint" (Belikov & Potapov
  2020), which only uses FIRE. Replaced by the FIRE paper (Hernandez-Matas et al., Modeling and Artificial
  Intelligence in Ophthalmology 1(4), 2017, https://doi.org/10.35119/maio.v1i4.42; the DOI resolves to "FIRE: Fundus
  Image Registration dataset") and the dataset page.

**`build_data.py`**
- The LIDC report flags were split over three places: `disagree()` in the worker, a positional tuple
  `(d5, rule, rule and not dup)`, and a second size-rule signature pass in the main process for the B2-4 counts.
  The worker now returns one dict per slice (`slice_flags`), and the main loop adds `{split}/{key}` for each entry.
  The B2-4 signatures are computed once, in the workers. The `lab_split_train_*` sums loop over the keys. The
  crowded-frame filter is a plain comprehension. The subset map is built once.
- Report keys, values and order (sorted JSON) are unchanged: the report is identical.

**`fetch_lidc_pixels.py`**: no change. It is small, and its only testable part (`choose`) is already minimal.

**Tests** (one copy of each assertion; every gate and break-it regression kept):
- `test_breakit_data.py`:
  - Removed `test_b3_6_*` and `test_b3_7_*`. F4's `test_data_store.py::test_write_rejects_one_item_id_in_two_splits`
    and `::test_write_enforces_image_dtype_and_layout` (the uint16 HU + 1024 case among 7) are supersets of them.
  - Merged `test_lidc_store_rows_keep_the_item_contract` into `test_data_lidc.py::test_store_lidc_val_rows_keep_the_item_contract`
    (formerly `..._items_are_distinct_raters_in_a_clear_frame`). One pass over LIDC val now checks the contract, the
    distinct layers (B3-3) and the clear frame (B3-2).
  - `test_b3_5_*` and `test_cache_loader_detects_swapped_caches` share a `prepared()` store builder and a `swap()`
    helper. The two LIDC nodules must differ in size: the frame crops around them, so same-size nodules would give
    identical caches and the cache swap would go undetected.
  - Removed the unused helper `rows()` and the constant `SERIES`. The header comment lists where each B3
    regression now lives.
- `test_data_store.py::test_flipped_byte_is_detected` became the `flip_middle` case of the break-it
  `test_store_tampering_is_detected` (5 attacks). That test now also checks that the error names the tampered file.
- `test_data_lidc.py`: imports moved to module level. The first docstring line said "the four fixes"; the parser now
  has rules P1–P6.

Gates kept: K10 (`test_same_items_same_bytes`, `test_store_rewrite_gives_identical_bytes`), K11 (`test_store_k11`,
`test_store_k11_keypoints` [slow]), P1–P3 unit tests, the pylidc parity sample, lab-fixture parity, the store tamper
tests, and every B3 regression (B3-1 … B3-8, I20).
