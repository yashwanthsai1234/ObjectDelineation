## What changed and why

**Library (`objdel.reward`, `objdel.eval`)**
- `reward.score_objects` (new, public): the single scoring pass behind `score_completion`. It returns the same terms
  dict plus, when the completion parses, each object's mask and `ObjectTerms` (`None, {}` otherwise).
  `score_completion` is now `score_objects(...)[0]`. Before, `eval.metrics._sample` called `score_completion`, then
  parsed, rasterized (polycore) and ran `score_mask` a second time on every distinct completion. That was M8's open
  issue "each distinct completion is parsed and rasterized twice". Now it takes one pass. Failed samples still get
  empty masks and their `score_mask`, as before. Sandbox `bench_eval.py`: 411 `metrics` calls on the golden val frames
  (honest, raters, union+honest models, plus one junk and one truncated sample each) give identical JSON, in 3.66 s
  instead of 4.54 s (0.81×). The training path is still literally the same code: TRL calls `score_batch` →
  `score_completion` → `score_objects`.
- `reward.topology_valid` (new, public): the r_topo validity gate, elementwise (legal, a rater drew the answer,
  `iou_min >= iou_gate`). `advantages_v4` / `topology_reward` and eval's `passed` now share one definition. They had
  two before. B2-7 was exactly a drift between those two copies. For `score_completion` outputs the old eval
  expression is equal to it (legal ∈ {0, 1}, `topo_freq > 0` ⇔ `topo_any > 0`), and the goldens confirm this.
- `cache._rater_stack`: one copy of the "(k ≥ 2, H, W) bool stack" check. `__init__` and `build` each had their
  own copy. `_crop` loses its unused `pad` option and uses `np.pad`.
- `eval.soft_dice`: the unused `thresholds` option is removed (always MRNet's `THRESHOLDS`).
- Citations: every URL in my modules was fetched (curl, HTTP 200, and the arXiv titles match the claims). The
  OpenCV docs page and ResearchGate return 403 to scripts only. I added the OpenCV header that states
  `DIST_MASK_PRECISE` + `DIST_L2` runs Felzenszwalb–Huttenlocher
  (https://github.com/opencv/opencv/blob/4.x/modules/imgproc/include/opencv2/imgproc.hpp, lines 3607–3608, read).
  I also added the book details of Cohn & Gotts (GISDATA 2, Taylor & Francis 1996; Leeds QSR publication list:
  https://www.ida.liu.se/ext/brs/A/Cohn/webpapers.html). The eval docstring now points at `score_objects` and
  `topology_valid`.

**Harness and variants (`tests/oracles`)**
- `topology_jitter(m, sig, min_area, amp, corr, rng)`: replaces three copies of "jitter, redraw up to 20 times
  until the size-filtered signature is the rater's". The copies were in `honest_pools`, `local_gradient_item` and
  `eval_demo._perturbed`. RNG consumption is identical, including the early stop when one rater fails.
- The harness's own copy of the exact EDT is replaced by `objdel.reward.cache.edt` (same 1e6 float32 sentinel, same
  OpenCV call). `packed(ObjectTerms)` defines the FIELDS order once, for `pack` and `reward_variants.pack_ab`. A
  `HOLES` constant is shared with `reward_gates`. Unused options are removed:
  `load_lidc_disagreement(split=)`, `punch_hole(centre=)` and `k9_groups(max_diou=)` (only the defaults were used).
- `reward_variants`: the two hole-arm wrappers become `partial(adv_v4_hole, field=...)`.

**Scripts**
- `reward_gates.py` (416 → 390). The K10 digest was written twice (in-process and as the fresh-interpreter
  source). Now the subprocess imports `digest` from the module. The scheme list duplicated `V.SCHEMES`, so it is read
  from there and threaded through no signature. Dead return values and the dicts that only fed them are removed
  (`k9_gate`, `adversary_table`, `neutrality_table`, `local_gradient` with its unused `rates`). So are the

  What is needed to reproduce the M6 gate table: every section is still emitted. The rest is table formatting

- `eval_demo.py`: `_perturbed` uses `topology_jitter`. The docstring is rewrapped and notes I19. `eval_run.py`:

**Tests**

## I19 (experiments import `tests.oracles`): decision, keep as is

The harness has 25 functions. Four test modules use them (`test_reward`, `test_reward_gates`, `test_eval`,
`test_eval_data`), and so do `reward_gates` (almost all of it) and `eval_demo` (`topology_jitter`, `adversaries`).
- Moving the helpers into the experiment scripts would make the pytest gates import scripts, or keep two copies.
  Two copies is the drift this design exists to prevent.
- Moving the harness into `src/objdel` would ship test-only code in the wheel (perturbations, adversaries, bootstrap
  CIs). It would also add about 250 statements that only data-backed tests cover, which lowers CI coverage (CI has
  no data; K13).
- A subpackage such as `experiments/phase1/harness/` is outside my paths. The library's unit tests would then import
  experiment code.

So I keep F5's decision: one harness in `tests/oracles`, imported through the editable install's repo-root `.pth`
under `-I`, which `test_experiment_scripts` checks. The module docstrings now say why (`reward_harness`,
`eval_demo`). `reward_variants` is used only by `reward_gates`, but it imports the harness, so moving it alone would
not close I19. Coordinator: mark I19 "won't fix (decided, F5 + S2)".

## M9 findings F1 and F2 (coordinator decision; `impl/M9_x86.md` "Findings and proposed fixes")

Both changes are test-first. Both new tests were red on the old code (`ZeroDivisionError` from the monkeypatched
OpenCV call / `quad`, then `AttributeError: _excursion_quad`).

**F1: `cache.edt` = `scipy.ndimage.distance_transform_edt(src).astype(np.float32)`.** The all-nonzero guard (1e6) is
kept.
- Why: on x86, the opencv-python wheel routes `DIST_L2 + DIST_MASK_PRECISE` to Intel IPP whenever the image has fewer
  than 2^14 px or OpenCV is single-threaded (`hal/ipp/src/distancetransform_ipp.cpp`). IPP's result is not correctly
  rounded and varies between runs (opencv#24082; PR #27432 only snaps near-integers). M9 measured sqrt(45) as both
  6.708204 and 6.7082043.
- scipy runs Maurer et al.'s exact feature transform, then a float64 `np.sqrt` of the exact integer squared distance
  (`ni_morphology.c`, `_morphology.py`, read). Rounding that to float32 gives the correctly rounded float32 sqrt,
  because double rounding is innocuous for sqrt when 53 ≥ 2·24 + 2 (Figueroa 1995; formal proof Roux 2014). OpenCV's
  own `trueDistTrans` on arm64 also gives the correctly rounded float32 sqrt of the exact integer.
- Sandbox `edt_eq.py` (Mac, IPP off): **103,311 masks bit-identical**. The masks are every fixture rater and its
  complement, every union complement and core, and 500 random masks up to 300². M9 measured the same on both
  architectures.
- Test `test_edt_is_correctly_rounded_without_opencv`: `edt` equals a brute-force `float32(sqrt(float64(d²)))` exactly,
  with `cv2.distanceTransform` monkeypatched to raise. It replaces the old 1e-4 comparison with
  `reward_reference.edt`, which uses scipy too, so independence now comes from the brute force.
- Cost (`bench_build.py`, 120 fixture objects each):
  - RIGA (465×417 crops): build 22.6 → 91.9 ms, load (rederive) 4.6 → 21.8 ms per object;
  - LIDC: build 0.8 → 1.2 ms, load 0.20 → 0.28 ms.
  This is paid only when a cache is built or loaded (training: `cache_loader`'s LRU), never per rollout. K3/K4 are
  untouched: `score_mask` uses the cached EDTs.
- Fingerprint: unchanged and kept as it is. OpenCV is still used for the cached values (`boundary`'s erosion feeds
  τ's contour distances and the perimeter), and scipy now also computes the EDT. Only the `spec.fingerprint`
  docstring changed (what each library computes). Stored caches (`data/prepared`) keep their digests on the Mac.

**F2: S_m frozen.** `cache.S_M` holds S_1..S_8 as `float.fromhex` constants. They equal the current Mac
`quad` values bit for bit (checked before freezing; M9's list). `excursion_moment(m)` returns `S_M[m]`, and falls back
to `_excursion_quad(m)` (the former code) for m > 8. No dataset has more than 6 raters, so behaviour is unchanged for
any k. Test `test_excursion_moment_is_frozen_and_equals_quad` checks:
- `|S_M[m] − quad| ≤ 1e-12` for m = 1..8;
- S_3 against its hex literal;
- m = 9 uses quad;
- with `quad` monkeypatched to raise, m ≤ 8 still works (not computed at run time).
`test_excursion_moment_matches_monte_carlo_and_reference` is kept.

**Golden check:** the whole S2 golden was rerun after F1 + F2. All 1,402 compared entries are byte-identical to the
pre-sweep values: caches 1,242 (digests, τ, T5, both EDTs), rollouts 37, harness 36 (+ `misc2` equal to the
post-sweep run) and eval 87.
