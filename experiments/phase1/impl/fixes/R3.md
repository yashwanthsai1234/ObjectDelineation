## #3: why the statistics were lost, and the choice

In transformers 5.20.1 `Trainer.evaluate` (`.venv/.../transformers/trainer.py`) runs `self.log(output.metrics)` at
line 2850 and `self.callback_handler.on_evaluate(..., output.metrics)` at line 2855. `Trainer.log` (line 4159) copies
the dict into `state.log_history` (`output = {**logs, "step": ...}`) and calls `on_log`, so whatever `on_evaluate`
adds to `metrics` reaches only the alarm and `evaluate()`'s return value (used for `metric_for_best_model`). The
docs also say callbacks are "read only" apart from `TrainerControl`, and that `metrics` is only passed to
`on_evaluate` (https://huggingface.co/docs/transformers/main_classes/callback). Searching found no hook that runs
after the evaluation's completions are scored and before that log: the reward is called per evaluation batch and
cannot know which batch is the last.

Choices:
- **The jsonl record (`stats=_flat(audit)`).** This is the review's minimal fix. It keeps every statistic, None
  included ("not measured"), next to `fired` / `new`. Only rank 0 writes it.
- **One extra log entry.** The plan §9 audit curves belong on the dashboards with the other `eval_*` curves, so the
  numeric statistics are also logged. I call `transformers.Trainer.log(self.trainer, ...)` and not
  `self.trainer.log(...)`, because `GRPOTrainer.log` (TRL 1.16, `grpo_trainer.py` line 3302) also averages and
  clears `_metrics[mode]`, rewrites `completions_<step>.parquet` and reprints the completions sample whenever
  `log_completions` is on, and none of that should happen twice. None values are left out of the log: the jsonl has
  them, and some `report_to` backends reject non-numbers (TRL itself turns all-NaN metrics into None for JSON
  loggers, which shows the same constraint). `eval_audit/fired` is a list, so it stays in the metrics dict (for the
  alarm) and in the event, and is not logged.
- Every process calls `Trainer.log`, the same as transformers' own `_maybe_log_save_evaluate`; the integrations
  check `is_world_process_zero` themselves.

The test runs the production `grpo_config` with TRLReward on real caches, scripted generation and
`eval_on_start=True`. It checks that `state.log_history` has `eval_audit/lidc/nodule/a_amax_median` ≈ 2.5 at steps
0 and 1, that `on_log` saw it twice, and that the jsonl `audit` events carry the same numbers. The three existing
audit tests are unchanged and pass.

## #7: one rule

TRL's rule is `eos_and_pad = [*self.eos_token_ids, self._tokenizer.pad_token_id]; ids[-1] not in eos_and_pad`
(`grpo_trainer.py` 2301-2302), where `eos_token_ids` comes from `model.generation_config.eos_token_id` plus the
tokenizer's EOS (lines 409-416). `rewards.stop_ids(model, processing_class)` builds the same set from the same
sources. It has to take (model, processor) rather than the trainer, because TRLReward is built before the trainer.
`sample` now calls it on `trainer.model` / `trainer.processing_class`. Under PEFT, `generation_config` is forwarded
to the base model. `truncated(ids, stop)` keeps the existing `not ids or ...` guard for an empty completion.

## #10: smoke output meaning

The keys `duplicate_rate`, `sigma_above_floor_any_term`, `groups`, `nonzero_adv_groups`, `adv_abs_max` and
`mean_<term>` keep their names and meaning ("the Phase 2 GRPO-signal numbers of this batch"). The first two now use
the gate's definitions: equal rasters, and the legality-gated geometric sigma (B2-6, `eval/metrics.py`). The
per-term diagnostic `sigma_above_floor_iou_tc` is dropped: the gate does not use it, and keeping it would mean
re-implementing part of the signal rule. The hook takes the batch's completions from `TRLReward.recorded`, the
same records the Controller audits, instead of TRL's private `_logs["completion"]`. A check on real prepared
caches (`scratchpad/impl/R3/real_group_stats.py`, 2 LIDC train items, 8 rater targets each, `python -I`) returns
`duplicate_rate` 0.5 and `sigma_above_floor_any_term` 0.0 and runs without error.

## Follow-up (coordinator, from R2): legality-gated selection metric

**Problem.** The TRL loggers returned `score_batch`'s raw `iou_tc` / `f5` / `g_area`. A parsed but illegal rollout
keeps its raw terms there (`score.py`: "kept for logging"). The Controller's default best-checkpoint metric,
`eval_rewards/iou_tc/mean`, is the mean of the `iou_tc` logger, so an evaluation of illegal answers with high IoU_tc
could become `best`. A g_area guard switch had the same gap: `w (g_area - mean)` credited illegal rollouts.

**Fix (`train/rewards.py`).** `GATED = ("iou_tc", "f5", "g_area")`. These loggers return `term * legal_gate(T)`,
which is exactly the term `advantages_v4` z-scores (`X = R * legal_gate(T)`). The rule is R2's
`objdel.reward.legal_gate`, so there is still one legality rule. The names are unchanged: `rewards/iou_tc/mean`,
`eval_rewards/iou_tc/mean`, and the Controller default all now mean "as the reward credits it". `format_ok`,
`legal`, `topo_any` and `r_topo` are unchanged (`r_topo` was already gated through `topology_valid`).

**Reward v4 stays byte-identical.** The aggregator still returns `advantages_v4(T)`, which
`test_values_equal_score_batch_and_advantages_v4` checks with exact list equality. TRL computes
`(rewards_per_func * reward_weights).nansum(dim=1)` (`grpo_trainer.py` 2763 / 2826). With weight 0, a logger adds
`0 * value = 0` for any finite value, so the sum does not depend on what the loggers return.
`scratchpad/impl/R3/byte_identical.py` rebuilds that sum in float32 torch for a batch with a spiked (illegal) answer.
Gated and ungated logger values give bitwise-equal sums (`torch.equal`), with 3 logger values differing. A guard
switch now adds `w (gated term - group mean)`. That is consistent with v4, and it only applies when someone sets a
logger weight.

**Tests (red first).**
- `test_train_rewards.py::test_an_illegal_high_iou_answer_does_not_raise_the_logged_geometry`: legal squares are
  replaced by a spiked square (IoU_tc 1, legal 0). Each gated logger logs 0 for them, its batch mean falls, and the
  aggregator equals `advantages_v4` exactly. It was red before the fix.
- `test_train_trl.py::test_an_illegal_high_iou_evaluation_never_becomes_best`: production `grpo_config` with real
  caches and scripted generation. A legal but less accurate policy is evaluated at step 0, then a spiked policy at

  logged value was 1.0, so step 1 became `best`.
