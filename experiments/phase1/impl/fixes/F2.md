## B2-4: sub-filter raters (decided: (a) abstain)

**Problem.** If every component of a rater's mask is below `min_area`, the rater's signature is `()`. That made
"nothing" a rater topology answer. A ≤ 4 px speck on that rater got IoU_tc 1 and F5 1, and a valid r_topo of
1.55–1.93.

**Census** (`census.py`, prepared caches):

| set | items | with a `()` rater | `()` rater is the only disagreement | every rater `()` |
|---|---|---|---|---|
| LIDC train (prepared) | 7,619 (311 disagreement) | 14 | 12 | 2 |
| LIDC val (prepared) | 1,085 (46 disagreement) | 1 | 1 | 0 |
| full-LIDC train disagreement set (gates; was 251) | 251 | 12 | 12 | 0 |
| fixture items (K8, K8b, R5, K9 fixtures, R3) | 1,002 | 0 | – | – |

**Research.**
- LIDC readers outline every nodule ≥ 3 mm on each CT slice where it appears; nodules < 3 mm get only a centroid
  (Armato et al. 2011, https://pmc.ncbi.nlm.nih.gov/articles/PMC3041807/). So a 2–11 px outline is the end-slice
  cross-section of a real nodule. It is not an answer "no nodule". At the reward's resolution (the size rule) it
  has no topology.
- Annotator models such as Dawid–Skene leave a missing label out of the likelihood. Only observed labels enter it
  (Stan User's Guide, "Data coding models", https://mc-stan.org/docs/2_32/stan-users-guide/data-coding-models.html;
  Passonneau & Carpenter, TACL 2014, https://aclanthology.org/Q14-1025/). An abstaining rater is that case.

**Alternatives compared** (`b24_exploit.py`, `b24_modes.py`). Groups are the abstainer-copying speck plus 7 honest
rollouts of the voting raters, 13 real items that have a voting rater, 40 groups each:

| design | speck beats the honest median (exact / 1 px / realistic honest) | speck r_topo | items kept in RL | code touched |
|---|---|---|---|---|
| before | 100 % / 100 % / 100 % | 1.55–1.93 | all | – |
| (a) abstain: not in the topology histogram or IoU_tc's rater set; still in the band, vote, area range, τ, T5 | **0 % / 1.5 % / 6.3 %** | 0 | all (geometry signal kept) | `reward/cache.py` (`voters`), shares over voters |
| (b) `rl_eligible` false | n/a (items dropped) | – | −14 train items (−12 ×4 oversampled rows) | F3's `prepare` |

With ad-hoc noisier honest rollouts (no 25 % exact share), (a) gives 15.8 %: mean speck A −1.20 against an honest
median of +0.53, where it was +2.74 against −0.07 before. The remaining wins are geometric only. τ on these items
is 1–7 px for 5–60 px nodules, inflated by the tiny rater itself, so realistic honest rollouts are poor. The speck,
lying inside the band, then out-scores them on F5 and g_area. It never gets the topology bonus. The R3 in-band
speck gate has the same order of residual (96.4 % below the median).

**Decision: (a).** The exploit is gone (r_topo 0; 0–6 % residual wins on geometry alone). K9 and R4 are unchanged on
every item that has no abstainer, because the terms are bit-identical there (`iou_min` = `iou_tc` for one object).
On the 251-item gate set, the 12 abstainer-only items stop being disagreement items, which leaves 239. (b) gives the
same gate numbers, since the same 12 items leave the set. But (b) needs a change in another owner's code, drops
the items' geometry signal, and leaves eval counting the speck as a rater mode. (a) is local to the reward and
fixes the root cause for any caller. Rule details:
- `voters(sigs)`: raters with a non-empty signature, or every rater when all abstain. On the 2 train items where all
  raters are 2–4 px, the unanimous answer "below the filter" stays valid, so nothing has an empty histogram.
- Multi-object (joint) answer: a rater votes when it votes in every object (`rater_answers`). RIGA has no abstainer.
- Eval uses the same `rater_answers`, so TV, JS, coverage and topology-any agree with the reward. A sample that
  copies the abstainer's speck is not a rater answer. R10 (raters' own targets perfect) still holds on the val
  sample in `test_eval_data.py`.
- Prepared data: τ/T5 values do not change (abstention is derived at load). The disagreement flag in
  `train.dataset._prepare` must use voters: `rec["disagreement"] = len(rater_answers(caches, names)) > 1` (F3).
  Expected counts after re-running `prepare_rl`: LIDC train 311 → 299 disagreement items (`grpo_rows(…, 4)`
  8,552 → 8,516), val 46 → 45.
- Gate harness: `load_lidc_disagreement` and `item_pools` (R4 classes) use voters. The gate set is 239 items
  (`tests/test_reward_gates.py` pins 239; renamed `lidc251` → `lidc_dis`).

## B2-7: per-object validity gate

`score_completion` returns `iou_min` = the smallest per-object IoU_tc. The topology validity in `advantages_v4` /
`topology_reward` reads it. Terms without `iou_min` (single-object callers, the packed harness, other agents' tests)
fall back to `iou_tc`, which is the same value for one object. Eval's `passed` now uses `iou_min` too (its separate
per-object loop was removed), so reward and eval have one definition. LIDC is single-object, so K9 / R4 / R3 are
unaffected by construction. RIGA effect, measured on the M8 demo outputs (per-object IoU_tc unchanged):

| RIGA model (demo) | outputs | valid by mean IoU_tc (before) | valid by every object (after) |
|---|---|---|---|
| raters' own targets | 384 | 100 % | 100 % |
| honest (U(0, τ) perturbation) | 384 | 99.2 % | 92.7 % (25 outputs with a cup IoU_tc < 0.5) |
| dilated union (64 copies) | 4,096 | 45.3 % | 3.1 % |
| dilated union + honest | 448 | 91.5 % | 79.9 % |

## B2-6: duplicates on rasters

`metrics` hashes, per distinct completion, `bytes([format_ok, legal]) + packbits(mask)` of every object. Eight
spellings of one mask (sub-pixel vertex nudges, appended whitespace) now count 7/8 duplicates. That is the same
notion as the reward's low-spread drop, which gives the group advantage 0. Both the plan §9 `duplicates` alarm and
the Phase 2 `grpo_duplicates` gate read it. Format failures share one hash: to the reward they are identical
outputs. Sources: numpy.packbits (https://numpy.org/doc/stable/reference/generated/numpy.packbits.html); DAPO
dynamic sampling, where identical rewards give a zero-signal group (https://arxiv.org/abs/2503.14476).

## B2-8: fingerprint and cache loading (reward side)

- **Libraries behind stored values.** τ uses OpenCV `distanceTransform` / `erode` and numpy `percentile`. T5 also
  uses scipy `integrate.quad` and `stats.norm` in S_m. Signatures, the vote and the band are rederived at load and
  need no fingerprint. `fingerprint()` = SHA-256 of (REWARD_V4, size-rule probes, numpy, OpenCV, **scipy**
  versions). Test: changing any of the three `__version__` strings changes it.
- **API that F3 / the coordinator rely on:**
  ```python
  ExpertCache.load(path, expected_digest: str | None = None, rebuild: bool = False) -> ExpertCache
  # ValueError("…SHA-256 mismatch…")             corrupted / edited file
  # ValueError("…cache and expected digests differ…")  the file is not the one the record names (checked on the file's own digest)
  # StaleCacheError(ValueError)("…another reward fingerprint…re-run prepare_rl or load with rebuild=True")
  #     built under another fingerprint; with rebuild=True: tau, T5 rebuilt from the verified masks (new digest)
  from objdel.reward import StaleCacheError
  ```
  F3's `cache_loader` already calls `ExpertCache.load(path, digest_from_record)`. A pin change now raises
  `StaleCacheError` with "fingerprint" in the message, not the misleading "digests differ". The rebuild path is
  reachable (`rebuild=True`) and tested (rebuilt T5 and digest equal a fresh build).
- **Consequence:** adding scipy changes the fingerprint, so **`data/prepared` must be rebuilt**
  (`.venv/bin/python -I -m experiments.phase1.prepare_rl`). τ/T5 values are identical; only the stored fingerprint
  string and digests change. Rebuild once, after F3's disagreement-flag change (B2-4). Until then these data tests
  fail: `test_breakit_wiring.py::test_real_lidc_sample_prepared_equals_store_and_eval_frames` (record digests ≠ fresh
  digests) and `test_train_dataset.py::test_r1_round_trip_on_the_prepared_train_set[riga|lidc]` (StaleCacheError).

## B2-9: rater counts across an item's caches

`rater_answers(caches, names)` (used by `score_completion` before parsing, and by eval) raises
`ValueError("the caches of one item need the same raters, got rater counts {…}")`. Rater *order* still cannot be
checked, because caches carry no rater ids. `prepare` builds every object from one item, so the order is right by
construction.

## B4-5: Phase 2 gates per dataset

`phase2_entry(report, datasets=None) -> {"pass", "datasets": {ds: bool}, "gates": {…}}`.
- Each judged dataset passes when every one of its gate values passes. The model passes when every judged dataset
  passes and at least one is judged.
- Default: the datasets in the report. `datasets=("riga",)` judges a model that the plan §7 precision probe dropped
  from LIDC. A requested dataset missing from the report fails, and so does a missing structure.

## Simplify

- One definition of the rater topology answer (`voters`, `rater_answers`) serves the reward, eval and (after F3's
  change) prepare. Eval's own rater-histogram loop and per-object pass loop were removed.
- One validity rule (`iou_min`) for the reward gate and eval's `passed`.
- One audit adapter (`alarms_for`); F3's duplicate was removed.
- `ExpertCache.load` checks the record digest itself, so callers need no separate comparison.
