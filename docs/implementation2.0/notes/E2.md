## Findings (evidence tags: [web: url] = read this session; [code: file:line] = read in repo; [unverified] = search snippet only)

### F1. Typed run specs: each repo picks one of four styles
1. verl: Hydra/OmegaConf YAML, a `defaults:` list with `group@target.path: option` entries and `_self_` last; some sections carry `_target_` and are turned into dataclasses by `omega_conf_to_dataclass` (AlgoConfig, KLControlConfig, ProfilerConfig). There is NO single base config class. CI enforces YAML format (comment above each field, blank line between fields). [web: raw.githubusercontent.com/volcengine/verl/main/verl/trainer/config/ppo_trainer.yaml]
2. NeMo-RL: Pydantic `BaseModel` configs (`GRPOConfig(BaseModel, extra="allow")`, typed fields with defaults, `MasterConfig` bundling policy/loss_fn/env/data/grpo/logger/cluster/checkpointing). `env` stays `dict[str, Any]`. [web: raw.githubusercontent.com/NVIDIA-NeMo/RL/main/nemo_rl/algorithms/grpo.py] (the excerpt did not show how YAML is loaded; not verified).
3. lerobot: `@dataclass` `TrainPipelineConfig` parsed with draccus (not Hydra, not Pydantic). One `validate()` runs every cross-field check (resolve pretrained sources, PEFT normalisation, defaults for job_name/output_dir, optimizer presets) and `_validate_distributed()` fail-fast rejects unsupported combinations. The config is saved as `train_config.json` next to the checkpoint and reloaded by `from_pretrained()` with legacy migrations. [web: raw.githubusercontent.com/huggingface/lerobot/main/src/lerobot/configs/train.py]
4. torchtune: YAML with `_component_: dotted.path` + `instantiate()` (recursive). Maintenance: one secondhand source says development wound down in 2025; repo shows v0.6.x as last tagged release. Treat as "do not copy, and do not depend on it". [unverified: pytorch/ao PR 4514 snippet; docs.pytorch.org/torchtune/main/generated/torchtune.config.instantiate.html]
5. OpenRLHF: plain argparse with dotted flags (`--actor.num_nodes`), `hierarchize(args)` nests them, then a validation block fills defaults (e.g. eps_clip_low_high from eps_clip, `ring_attn_size>1` forces `packing_samples`). [web: raw.githubusercontent.com/OpenRLHF/OpenRLHF/main/openrlhf/cli/train_ppo_ray.py]
6. TRL: `GRPOConfig` is a dataclass inheriting TrainingArguments; knobs we use are documented: `loss_type` (dapo default, dr_grpo, sapo, cispo, vespo), `vllm_mode` colocate (default) / server, `vllm_enable_sleep_mode`, `vllm_importance_sampling_correction` (default True), `vllm_importance_sampling_mode` (default sequence_mask), `vllm_importance_sampling_clip_max` (default 3.0). [web: huggingface.co/docs/trl/main/en/grpo_trainer]
- tyro (CLI from dataclasses/functions, nested structures, subcommands, static types) is a CLI layer only. The page I read did not confirm Pydantic or config-file support. [web: brentyi.github.io/tyro/]

Pattern across all: (a) one typed object is the single source of truth; (b) cross-field validation lives in one place and fails before any GPU is used; (c) the resolved config is saved with the run.

### F2. Our current state [code]
- Run spec = YAML whose `steps:` are raw argv lists with `{rd}`/`{data}` placeholders (experiments/phase2/configs/rl_shifted.yaml:16-24). No types: a typo in `--train-views` is found only on the GPU box. The run intent (e.g. "300 steps, shared-prefix, train views X and Y") is only in a comment header.
- Training settings are a module of functions plus a 60-line docstring (src/objdel/train/configs.py:1-60). Reward constants are a frozen dataclass `RewardV4` with a SHA-256 fingerprint (src/objdel/reward/spec.py:1-30). This is a good pattern: frozen + hashed + versioned name. Keep it.
- `fast.py` imports `trl.trainer.grpo_trainer as trl_grpo` and `GRPOTrainer` directly and monkey-patches (src/objdel/train/fast.py:25-26). pyproject pins trl==1.17.1, torch==2.14.1, transformers==5.20.1 (pyproject.toml, `train` extra). Note: configs.py docstring still says "TRL 1.16", stale.
- No import-linter in pyproject or Makefile (grep: no hit). Packages: checker, data, eval, geometry, reward, targets, train (src/objdel).

### F3. Layer enforcement: import-linter fits exactly
- Contract types: forbidden, protected, layers, independence, acyclic_siblings; custom types allowed. Config in INI or TOML (`[[tool.importlinter.contracts]]`). Wildcards `*` (one level) and `**` (all sub-levels), whole module names only. `ignore_imports` with `unmatched_ignore_imports_alerting` (default error, so stale exceptions are flagged). [web: import-linter.readthedocs.io/en/stable/contract_types/]
- Layers: ordered high to low; `containers`; `exhaustive = true` (every module in the container must be listed, so a new package cannot escape the rules); `exhaustive_ignores`; optional layer `(name)`; independent siblings `a | b`; `:` for siblings that may import each other (do not mix `|` and `:` on one line). [web: import-linter.readthedocs.io/en/stable/contract_types/layers/]
- Not confirmed from the pages I read: whether a layers contract sees third-party imports. Use a `forbidden` contract with `include_external_packages` for torch/trl bans; verify before relying on it (see Open questions).
- Adoption in the named RL repos: I found no evidence that verl, NeMo-RL, TRL, torchtune, OpenRLHF or lerobot use import-linter. [not found; absence of evidence only]. They rely on convention and CI lint. So this is a rule we add beyond them, and is cheap.

### F4. Adapter around a pinned framework
- NeMo-RL exposes a `policy_factory` hook so callers substitute a Policy class, and wraps `EnvironmentInterface` from `nemo_rl.environments.interfaces`. [web: grpo.py excerpt above] This is the same idea as an adapter, at the algorithm/env seam.
- verl documents an external-module loader: env var `VERL_USE_EXTERNAL_MODULES` imports user modules so their registration hooks run without editing verl. [unverified: search snippet of verl extend_guide]
- TRL itself is built to be extended via callbacks and callables: reward functions are plain callables, `reward_funcs` accepts list, weights via `reward_weights`; `None` from a reward func drops that func for that sample. [web: huggingface.co/docs/trl/main/en/grpo_trainer]
- Implication: our `fast.py` reaches into TRL private names (`trl_grpo` module attributes). That is the exact thing an adapter should concentrate in one file with a start-up version/symbol check (matches phase A "TRL private-name start-up check").

### F5. Plugin registries and versioned reward/verifier APIs
- verl: reward function by file path + name (`custom_reward_function.path`, `.name`), reward manager chosen by `reward_model.reward_manager` (default naive) and, in the reward-loop docs, a `@register("name")` decorator on a `RewardManagerBase` subclass selected by `reward.reward_manager.name`. Signature of a user function: data source, solution string, ground truth, optional extra info, returns float. [unverified: search snippets, verl.readthedocs.io/en/latest/advance/reward_loop.html, verl.readthedocs.io/en/v0.3.x/preparation/reward_function.html]. Unversioned.
- OpenRLHF: reward by `--reward.remote_url` (HTTP RM, comma list), `--reward.model_name_or_path`, or `--train.agent_func_path` (forces remote_url="agent"). Unversioned. [web: train_ppo_ray.py]
- TRL: reward callable gets `prompts, completions, completion_ids, trainer_state, log_extra, log_metric` plus every dataset column as kwargs; returns list[float] (or None per sample); sync or async. [web: trl grpo docs] Unversioned, but extra keyword args are additive, which is a safe evolution rule.
- None of the repos I read version their verifier. Our `REWARD_V4` + fingerprint (hash includes numpy/scipy/cv2 versions) is AHEAD of them. Keep and extend (name + semver + fingerprint in every result). [code: src/objdel/reward/spec.py]
- Registries: used for reward managers (verl) and policy types (lerobot, via draccus ChoiceRegistry in its policy configs; NOT in train.py, which I read) [web: train.py note]. They exist where several implementations really coexist.

## Recommendations (numbered)

Stack decision (one line): **Pydantic v2 frozen models for the run spec + YAML files + tyro for the CLI + import-linter in `make lint` + one TRL adapter module + the existing frozen-dataclass reward spec. No Hydra, no registry framework.**

Why not Hydra/OmegaConf: verl needs it for 100+ composable groups (actor/ref/rollout/critic). We have ~16 yaml plans, one model family, one algorithm. Hydra's group composition and `_target_` instantiation add magic we would debug. Why not draccus/lerobot style: Pydantic gives JSON-schema export, strict validation (`extra="forbid"`), frozen models, `model_validator` and discriminated unions, and NeMo-RL already shows it works for GRPO. Why tyro: gives `--help` and CLI overrides from the same model with static types; verify its Pydantic path (Open question 1) else use `pydantic-settings` CLI or plain `Model.model_validate(yaml)` and a tiny `--set key=value` override.

1. **Typed run spec.** New `src/objdel/spec/` (layer: top-level contract, imports nothing heavy; no torch, no trl). Files:
   - `spec/run.py`: `class RunSpec(BaseModel, frozen=True, extra="forbid")` with fields `schema_version: Literal[1]`, `name: str`, `phase: Literal["sft","rl","eval","probe"]`, `model: ModelSpec` (name, ckpt, max_completion_length), `data: DataSpec` (prepared path, `train_views: list[str]`, view mix weights, split), `rl: GrpoSpec` (steps, num_generations=8, loss_type="dr_grpo", beta, vllm_importance_sampling_mode, vllm_importance_sampling_clip_max, micro_batch, accumulation), `fast: FastSpec` (shared_prefix, vision_cache, no_merge_sync, open_once), `reward: RewardRef` (name "objdel.reward", version "v4", fingerprint), `compute: ComputeSpec` (gpu, cap_hours, budget_usd, regions=["US","CA"]), `eval: list[EvalSpec]`.
   - `spec/validate.py`: cross-field rules in `@model_validator(mode="after")`, copied from today's prose/ValueErrors: `num_generations == reward.group` (configs.py: "any other num_generations raises ValueError"); per-device batch is a multiple of `num_generations`; `train_views` non-empty when `phase=="rl"` and `data.require_shifted=true` (owner rule: data first); `regions` must be NA only (policy rule). Fail-fast like lerobot `validate()`/`_validate_distributed()`. [web: lerobot train.py]
   - Config files stay YAML in `experiments/<phase>/configs/*.yaml`, loaded by `RunSpec.model_validate(yaml.safe_load(...))`. Replace the `steps:` argv lists: the launcher derives argv from the spec (`spec/argv.py: to_argv(spec, step) -> list[str]`), so there is one definition of each flag.
2. **Save the resolved spec with every run** (lerobot saves `train_config.json` and reloads it [web: train.py]). Write `{run_dir}/run_spec.json` = `spec.model_dump_json()` + git sha + pins (trl/torch/transformers versions) + reward fingerprint + target-set hash. `objdel.eval` refuses to score a checkpoint without it.
3. **CLI.** `experiments/<phase>/<script>.py` does `spec = tyro.cli(RunSpec, default=load_yaml(path))` (verify, Open question 1). Rule: no script defines its own argparse flags that duplicate a spec field.
4. **Layers (import-linter).** Add `import-linter` to the `dev` extra and a `make lint` step (`lint-imports`). TOML in pyproject:
   ```toml
   [tool.importlinter]
   root_package = "objdel"
   [[tool.importlinter.contracts]]
   name = "objdel layers (high imports low)"
   type = "layers"
   containers = ["objdel"]
   layers = ["infra", "sft | rl", "policy", "data", "verify", "geometry"]
   exhaustive = true
   exhaustive_ignores = ["secrets", "spec"]
   [[tool.importlinter.contracts]]
   name = "pure core never imports the ML stack"
   type = "forbidden"
   source_modules = ["objdel.geometry", "objdel.verify", "objdel.data"]
   forbidden_modules = ["torch", "trl", "transformers", "peft", "vllm", "datasets"]
   include_external_packages = true
   [[tool.importlinter.contracts]]
   name = "only the adapter touches TRL"
   type = "forbidden"
   source_modules = ["objdel"]
   forbidden_modules = ["trl"]
   allow_indirect_imports = true
   ignore_imports = ["objdel.rl.trl_adapter -> trl", "objdel.rl.trl_adapter.* -> trl"]
   ```
   (`include_external_packages`, `allow_indirect_imports` and the `ignore_imports` form are from my memory of the docs; the pages I read confirmed only the layers options and ignore_imports syntax. Run `lint-imports` once and fix before trusting. Open question 2.)
   Map to today's packages: geometry = objdel.geometry (+ objdel.targets geometry parts); verify = objdel.checker + objdel.reward score/spec/advantages; data = objdel.data + objdel.targets; policy = prompt/format/parse of polygon text (objdel.geometry.text today); rl = objdel.train rewards/dataset/sample/fast; sft = train_sft pieces; infra = vast/launch/hf push. Use `exhaustive = true` so a new package cannot skip a layer. `unmatched_ignore_imports_alerting` stays at its default `error` so temporary exceptions cannot rot. [web: contract_types pages]
   Rule of use: every `ignore_imports` entry needs a comment with an issue/date; goal is zero.
5. **TRL adapter (one seam, one file).** Create `src/objdel/rl/trl_adapter.py` (the ONLY file importing `trl`). It exports: `build_trainer(spec: RunSpec, policy, reward, dataset) -> Trainer`; `assert_pins()` that checks `trl.__version__ == "1.17.1"` and that each private symbol `fast.py` patches still exists (`hasattr(trl_grpo, "<name>")`, list in one tuple `PATCHED_SYMBOLS`); `to_grpo_config(spec.rl) -> GRPOConfig`. Move `fast.py`'s patches in as `rl/trl_adapter/fastgrpo.py` (patches applied by `apply(spec.fast)`, each flag-guarded, each with its own test against a tiny model). Reasons: (a) pinned framework drift is caught at start-up, not 30 minutes into a paid run; (b) the 732-line fast.py gets a named boundary so CLEAN can delete patches that TRL ships upstream; (c) deletion test: if the adapter vanished, TRL calls would spread across train_rl, g_probe, profile, sample_vllm, so it earns its keep. Do NOT create an abstract `Trainer` interface: one adapter = hypothetical seam (codebase-design rule). The `Reward` callable below is the second seam and the only one with 2+ real implementers (verifier v4/v5, GPU and CPU scorer).
6. **Verifier / reward API (versioned, additive).** New `src/objdel/verify/api.py`:
   ```python
   API_VERSION = "1.0"          # semver: minor = additive fields only; major = breaking
   class VerifyRequest(BaseModel, frozen=True): outline_text: str; image_id: str; window: Window; rater_masks_ref: str
   class VerifyResult(BaseModel, frozen=True):
       api_version: str; reward_name: str; reward_version: str   # "v4" | "v5"
       fingerprint: str; legal: bool; defects: list[DefectCode]   # 13 classes
       iou: float; boundary_f: float; area: float; betti: tuple[int,int]
       reward: float | None   # None = excluded, same meaning as TRL's None
   class Verifier(Protocol):
       def verify_batch(self, reqs: Sequence[VerifyRequest]) -> list[VerifyResult]: ...
   ```
   Rules (from api-design): additive changes only within a major; unknown keys forbidden on input, tolerated on stored output; one stable error shape (`DefectCode` plus message, never an exception for a model-made bad outline); the result carries `reward_version` + `fingerprint` so a stored `ExpertCache` or eval json can never be mixed across versions (extends today's ExpertCache fingerprint in reward/spec.py). The TRL reward callable is a 10-line wrapper in the adapter: `def reward_fn(completions, **cols) -> list[float|None]` calling `verify_batch`. Pixels never return to CPU: `VerifyResult` holds scalars only (matches the GPU-scoring rule).
7. **Registries: only two, tiny, explicit.** `verify/registry.py`: `VERIFIERS: dict[str, Callable[[], Verifier]] = {"v4": ..., "v5": ...}` keyed by `reward.version` in the spec. `rl/registry.py` is NOT needed (one algorithm: GRPO, loss variants are a TRL string). No decorator magic, no entry points, no dynamic path loading (verl's `custom_reward_function.path` is a code-execution surface we do not need; data is untrusted). Add a registry for models only when a second model family needs different image/processor code (today's `ModelSpec` table in configs.py is enough).
8. **Frozen constants stay frozen dataclasses with a hash.** Keep `RewardV4`; add `RewardV5` beside it, never edit v4 (changing a value = new class, per the module docstring). Test: `fingerprint(RewardV4()) == "<pinned literal>"` in tests/ so an accidental edit fails CI.
9. **Config hygiene copied from verl CI:** a test that loads every `experiments/*/configs/*.yaml` through `RunSpec` (fails on typos or stale plans) and `make preflight` calls the same validator before any rental. This is the "no spend before scan" rule made executable. [verl enforces YAML format in CI; web: ppo_trainer.yaml]
10. **Do not adopt:** Hydra/OmegaConf, torchtune `_component_` instantiation, `extra="allow"` (NeMo-RL uses it; it hides typos), ClearML/registry plugins, a microservice split. Single GPU box, single process: modular monolith with import-linter enforced seams (service-decomposition skill).
11. **Docs:** one page `docs/architecture/layers.md` that shows the layer table and says "source of truth is `[tool.importlinter]` in pyproject.toml" (link, no copy). ADRs listed below go in `docs/decisions/`.
12. **Migration order (cheapest first):** (1) add import-linter with `exhaustive=false` and generous `ignore_imports`, make `make lint` pass; (2) add `RunSpec` + validator + yaml-loads-test, port `rl_shifted.yaml` first; (3) extract `trl_adapter.py` with `assert_pins()`; (4) `verify/api.py` wrapper around the existing checker; (5) turn on `exhaustive=true`, delete ignores; (6) archive argv-style yaml plans (CLEAN).

## ADR candidates
- ADR: Pydantic v2 run spec over Hydra (context: 16 plans, 1 algorithm; consequence: no group composition, simple debug).
- ADR: TRL touched only via `rl/trl_adapter`; pins asserted at start-up.
- ADR: Verifier API semver + fingerprint in every result.
