### F1. What final_eval does today
- `experiments/phase2/final_eval.py:26-30` `per_item` keeps K-sample means of only 7 numbers: legal, iou_tc, f5, precision_vote, recall_vote, dice_vote. It drops everything else `metrics()` computes. [code: final_eval.py:23,26-30]
- `final_eval.py:33-43` `summarize`: plain ITEM bootstrap (`rng.integers(0, n_items, (2000, n_items))`), 95 % percentile. Items from one nodule (about 5.5 images each) are treated as independent. [code: final_eval.py:36-38]
- `final_eval.py:71-72` the K texts exist in `done` (sample.sample output) but are never written. `items.jsonl` holds only the 7 means. So best-of-8, medoid and pixel vote cannot be computed after the fact. [code: final_eval.py:65,76-78]

- Time: load_and_sample 630 s of 634 s total on test. Scoring costs about 3 s. [measured: runs/r5/eval/eval_test/final_eval.json seconds]. So metric speed does not matter; correctness and GPU-only rule do.

### F3. The ceiling is not computed by any committed script, and it is not matched to the model's metric
- 0.732 (test) and 0.734 (val) appear only in prose: Research2.0.md:283, rl_plateau_diagnosis_2026-11-08.md:40-42, Direction.md:327. Definition in the note: "mean over doctors of the best IoU against the other doctors (leave one out; it ignores topology)". [code: docs/research/notes/rl_plateau_diagnosis_2026-11-08.md:40-42]. No file under src/ or experiments/phase2/*.py computes it. The nearest code is `experiments/phase2/lab/A4/rater_ceiling.py:62-70` (per-rater LOO IoU_tc analogue, LOO D_max, LOO IoU vs vote), which is a lab sandbox run on val only (`store.load(dataset, "val", ...)`, line ~50). So the test ceiling cannot be reproduced from the repo. [code: lab/A4/rater_ceiling.py:47-70]
- Two definition gaps:
  1. Ceiling uses best IoU over the OTHER k-1 doctors with no topology rule. The model's IoU_tc is "highest IoU against raters who drew the same signature, else IoU against the vote" [code: docs/glossary.md:59], against ALL k doctors. The model gets one more reference (k vs k-1) and a topology-aware score. Direction.md A2 / Research2.0 4.8 name the first gap only.
  2. A doctor's number should be computed by the same function as the model's, on the same reference set, so the model-minus-doctor difference is paired per item.
- Rater counts of RL-eligible LIDC items [measured: data/prepared/lidc/{train,val}.jsonl]: val k=2: 281, k=3: 330, k=4: 473 (26 % have k=2); train k=2: 1,933, k=3: 2,029, k=4: 3,379.
- Edge case that decides the design: `ExpertCache.build` refuses fewer than 2 raters (`_rater_stack` -> `rl_eligible`, src/objdel/reward/cache.py:203-207,264-266). Leaving one doctor out of a k=2 item leaves 1 reference: no ExpertCache, so the reward scorer (`score_mask`, score.py:68-77; device tables via `cache.device()`) cannot score it. 26 % of items are k=2.
- `ExpertCache(raters, tau, t5)` also computes tau and T5 (EDT, second moments) that iou_tc does not need (cache.py:222-238). Building 3 LOO caches per item on 2,200 items is a CPU cost of order seconds-to-minutes [estimate], fine on Mac.

### F5. Medoid / legal-first selection (A4) has the ingredients
- Pairwise IoU matrix of the K samples is already built per object: `iou = _pairwise_iou(concatenate([drawn, raters, vote]))` (metrics.py:307-309); `iou[:K,:K]` is the sample-sample block. Medoid = argmax over legal samples of mean IoU to the other legal samples. No labels used (raters are only in other blocks).
- Selecting needs `legal` per sample (metrics.py:301 `legal_gate(T)`), the sample texts (not saved today, F1), and for nodule one object. For RIGA two objects: use the mean of the two objects' sample-sample IoU.
- Pixel vote (A4 gate mention): a mask, not a text. It can be scored with `score_mask` (score.py:68) but cannot be output by the model; the production polygonizer (src/objdel/checker/polygonize.py) or CUDA `check_masks` would have to turn it into a polygon. Report it as an analysis number, not a deployable answer, until D-phase CUDA polygonizer lands.
- Headline 0.645 is the mean over K=8 samples at T=1 (final_eval.per_item = np.mean over samples). Selecting 1 of 8 is a different protocol. Always report four paired lines per item: mean-of-K (today), medoid, oracle best-of-8 (labels, upper bound, not deployable), random-1 (= mean-of-K in expectation). Gate A (+0.015 with CI above 0) must use the nodule-cluster paired CI (`signal.paired`, signal.py:139-151).
