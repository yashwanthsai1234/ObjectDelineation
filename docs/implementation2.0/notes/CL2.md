### 1. Polygon text parsing: src/objdel/geometry/text.py (173 lines)
- Does: strict grammar, regex fullmatch, then json.loads, error codes for typed logs, 16,384-char cap, regex reused for vLLM structured output [code: geometry/text.py:1-40].
- Candidates: pydantic 2.14.3 [pypi, 2026-11-05] (`model_validate_json`), msgspec, orjson, shapely `from_geojson`/`from_wkt`, lark/pyparsing.
- Evidence: pydantic cannot give the exact error codes and the "no leading zero, 0..1000 ints, no Unicode digits" grammar without custom validators; `from_wkt` parses a different grammar. The parser is already "regex + C json.loads", 5-6x faster than the hand recursive-descent oracle [code: text.py docstring, M2 note]. The same regex feeds TRL `vllm_structured_outputs_regex`, which a pydantic model would not give.
- Verdict: KEEP. No library does less custom work for this strict grammar. The only change: the 150-line hand-written oracle `_Lab` in tests/test_geometry_oracle.py [code: tests/test_geometry_oracle.py:1-30] is a test of a deleted-lab parser; keep as differential test only if cheap, else drop (see Rec 9).

### 2. Geometry canonical form + legality: src/objdel/geometry/shape.py (149 lines), checker/*.py (~400 lines), cuda/gpucheck.cpp (1,835 lines)
- Candidates: shapely 2.2.0 [pypi 2026-10-07; web: https://shapely.readthedocs.io/en/stable/release/2.x.html; GEOS 3.14.1 wheels; Python >=3.11]; `shapely.is_valid_reason`, `make_valid`, `contains_xy`, `orient_polygons`; rasterio.features.shapes; skimage.draw.polygon2mask; cv2.fillPoly.

It does not know our 13 classes or grid/min-area rules, so it can only cross-check the subset that is OGC validity. [estimate] covers 4-6 of 13 classes; I did not verify which classes map (open question 2).
- Verdict: KEEP the CUDA checker and canonical form (shape.py is 149 lines and mirrors the hashed target order). ### 4. Stats / bootstrap: src/objdel/eval/signal.py (205 lines)
- Candidate: scipy.stats.bootstrap (scipy 1.18.1 [pypi 2026-08-21]; repo requires scipy>=1.13).
- Evidence [web: https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html]: parameters data, statistic, n_resamples=9999, vectorized, paired, axis, confidence_level, alternative, method in {percentile, basic, bca}, rng. No cluster or group argument. `paired=True` resamples the same indices across arrays but at row level, not at nodule-cluster level. So the repo's `draws()` (resample nodule groups, concatenate their rows) [code: eval/signal.py:102-107] cannot be replaced directly.
- A clean way: resample CLUSTER MEANS. Per-image metrics -> aggregate to per-nodule arrays, pass them as `data` to scipy.stats.bootstrap (`method="percentile"`, `paired=True`, `vectorized=True`, `rng=seed`). This changes the estimator when clusters have unequal image counts (cluster-mean vs pooled mean), so it moves the CIs. Not a drop-in.
- Current implementation cost: a Python loop of `boot` draws, each `np.concatenate` over groups, and `_ci` calls f(d) per draw [code: signal.py:102-116]. For 2,200 test images and boot ~ thousands it is slow but not a bottleneck [estimate; not measured].
- Better: vectorize with a group-size weight matrix: counts = multinomial draw of cluster indices (boot x n_clusters), then weighted mean = counts @ cluster_sums / counts @ cluster_sizes. This is exact for mean statistics, no concat, one matrix product, optionally on GPU (torch/cupy). Spearman/median still need per-draw index lists.
- Verdict: KEEP the cluster logic (no library does it), but REPLACE the loop for means with the weight-matrix form and use `scipy.stats.bootstrap` only for non-clustered checks. Keep `np.nanquantile` percentile CIs: same as method="percentile". Test: new vs old CI equal for same seed is NOT guaranteed (RNG draw order differs); gate by statistical agreement within MC error, then re-record goldens.

### 5. Metrics / geometry on masks: src/objdel/eval/metrics.py (401 lines), reward/cache.py (293), data/riga.py, checker/topology.py, checker/volume.py
- Parts: Dice/IoU, GED, HM-IoU (Hungarian via scipy linear_sum_assignment), NSD with surfel table + scipy EDT, EDT/erode in cache.py, CCL via cv2 Spaghetti, Betti numbers.
- Candidates and evidence:
  - cuCIM 26.10: `distance_transform_edt` (GPU), `measure.label`, `euler_number` (Betti numbers from Euler number partly), `regionprops`, morphology. CuPy 14.2.0 [pypi 2026-08-20] has `cupyx.scipy.ndimage` (label, EDT, binary ops). Both fit "GPU everywhere".
  - MONAI 1.6.1 [pypi 2026-09-27] has Hausdorff/surface-distance/Dice metrics; torchmetrics 1.9.0 [pypi 2026-03-09] has Dice/IoU; google-deepmind surface-distance 0.1 [pypi 2024-07-30, stale]; MedPy 0.5.2 [pypi 2024-07-24, stale]. NSD with our surfel-length weights is the DeepMind definition; the DeepMind package is unmaintained, so do NOT adopt.
- The reward numbers are hashed (REWARD_V4 fingerprint with numpy/scipy/cv2 versions [code: reward/cache.py:119]). Replacing EDT/CCL with cuCIM results in float differences at ties (EDT cuCIM computes exact EDT, float32 default; flag `float64_distances` exists [web: cuCIM docs]) and different label order. The CUDA engine (cuda/gpucheck.cpp) already does masks + IoU/F/area/topology on device [BRIEF §1]; the remaining CPU metrics are eval-only (GED, HM-IoU, NSD).
- Verdict: KEEP in the reward path (already CUDA, hashed). For eval-only metrics (GED, HM-IoU, NSD, soft Dice): optionally move EDT to cuCIM/CuPy in Phase D "GPU EDT/GED/HM-IoU"; `scipy.optimize.linear_sum_assignment` for HM-IoU stays (K x k <= 8 x 4 is tiny; no GPU gain). Do not adopt MONAI just for metrics: it pulls torch-version pins and does not implement GED / HM-IoU / multi-rater set IoU [estimate: from MONAI metric list as I know it; not re-verified].
- cv2 Spaghetti CCL on CPU for topology (checker/topology.py:77): cuCIM `measure.label` or CuPy `ndimage.label` replace it on GPU, but the CUDA engine already has topology; delete the host path only after the CUDA path covers all callers (Phase D).

### 7. Data store: src/objdel/data/store.py (199 lines): Parquet per (dataset, split), NPY bytes in zstd, SHA-256 manifest, deterministic bytes [code: store.py:1-35,60-70]
- Candidates: HF `datasets` 5.1.0 (already pinned in `train` extra) with Image/Array feature + `push_to_hub`; polars 2.1.0 [pypi 2026-10-25]; DuckDB; pyarrow 26.0.1 [pypi 2026-11-03]; WebDataset; Zarr/NGFF; pycocotools RLE 2.0.11 [pypi 2025-12-15].
- Evidence: the store already IS pyarrow Parquet (the thing polars/datasets would wrap); its custom value is exact dtype (int16 HU), bit-packed masks, per-file SHA-256 and sorted-row determinism (K10), and leakage checks (id unique across splits). - Verdict: KEEP pyarrow store. REPLACE nothing. Cheap win: delete `_sha256` helper only if `hashlib.file_digest` (Python 3.11+) is used (repo requires >=3.12): 3-line saving.
