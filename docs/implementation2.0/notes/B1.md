## What the data path is (code read)
- `targets/frame.py`: policy frame = square window around the union of all doctors' masks, side S = smallest divisor of 1000
  >= extent + margin (max(8 px, 25 %)), min 50, so 1 px = 1000/S grid units exactly; HU lung window [-1000,400] -> uint8;
  Pillow bicubic to 512. `frame(item, offset, side, window)` moves/resizes the window, ValueError unless union is inside with
  CLEARANCE = 2 px and no other outlined nodule is in the window (`crowded`). Defaults skip both checks.
- `targets/augment.py`: D4 ops, `draw` (S uniform over policy side and LADDER neighbours; uniform offset by rejection, 200 tries),
  `neighbour_side` (eval "rescaled"), `jitter` (window level -300+-60, width 1400+-80, noise sigma<=10 HU), context crops, `row_rng` (SHA-256 seeded).
- `experiments/phase2/build_views.py` = SFT bundle (rows per voting doctor, 3-4 epochs, D4 + HU jitter, non-simple x4).
  `build_eval_views.py` = one fixed window per item per kind (shifted, rescaled, rotated), seed 0, with PNG + ExpertCache per view.
- RL rows: `train_rl --train-views` -> `dataset.grpo_rows_views` = prepared (centred) + shifted + rescaled train roots, disagreement items x4,
  keys tagged `i::item`; each row is scored on its own window's caches. Rows are per ITEM (slice), not per doctor.
- Stores: `data/store/lidc/{train,val,test}.parquet` (7,341 / 1,084 / 2,200 items, int16 HU, bit-packed masks).

F9. Data-provenance risks to check. [measured items; web claim unverified]
- Quoting a third-party redistribution, 5 LIDC series have duplicate-z DICOM slices (LIDC-IDRI-0085, -0146, -0418, -0572, -0979) [web: https://huggingface.co/datasets/YongchengYAO/LIDC-IDRI-Lite]; TCIA lists an XML error for -0396 and an invalid attribute for -0510 [web: https://wiki.cancerimagingarchive.net/x/9AA9 and the TCIA LIDC-IDRI page, via search summary].
  Our store holds items of 0085 (val 2), 0146 (val 15), 0572 (train 12), 0510 (train 55): 84 items (0.8 % of 10,625). `lidc.slice_index` picks the nearest z, which is ambiguous when two slices share a z. Not verified against the raw DICOM: open question Q2.
- LIDC counts reconcile: 1,010 patients, 1,018 series, 8 two-timepoint patients [web: TCIA LIDC-IDRI wiki via search]; our 793 patients / 800 series in the store (items need >= 2 doctors on a slice >= 3 mm) is a subset, as designed.

F10. Code observations in the data path (code-review lens; no REPO edit).
- `frame.py`: `moved` flag skips CLEARANCE/crowded checks for the policy window; consequence is nil today (F2: 0 crowded) but the invariant "no other outlined nodule in the window" is not enforced for the policy window, so a new split could break it silently. Add the check as an audit gate, not in `frame`.
- `augment.draw`: sides come from `sides(item)`, always includes policy S, so no S=50 downscale ever exists (LADDER floor 50). Fine, but "uniform over sides" gives rows with 2 sides for S0<=125 and thus 50/50 mix for most items (explains F4 SFT S mix).
- `shift`: offsets are uniform over the admissible RECTANGLE, so objects far from the centre are as likely as near; large objects have almost no room (offset small). That is why ext_frac correlates with offset and why train (larger objects) has a smaller offset than test (smaller objects). A better match is to condition on object size or to sample offset by target distribution (R2).
- `build_eval_views.py` builds all three kinds and the config then `rm -r`s two of them (rl_shifted.yaml comments). Add `--kinds shifted`.
- `grpo_rows_views`: no stratification by nodule; no check that the three roots share the same item set and seed (`prompts()` verifies each image sha but not cross-root consistency; only the cache keys tie them).
- Deterministic-order issue: `prompts(... oversample)` repeats disagreement rows x4 in a row (adjacent in the list). With shuffling this is fine; with `RepeatSampler` (32 images x 8) a repeated item can land twice in one step. Check the sampler seed; not measured.

## Recommendations (numbered, concrete)

R1. Promote the audit to a library + CLI + tests. New `src/objdel/data/audit.py` (functions `window_stats(items, kinds, seed)`, `mix_stats(roots, weights)`, `leakage(store)`, `gate(report) -> list[Failure]`) and `experiments/phase2/audit_views.py` (module run with `-I`; prints the G1-G21 table, exits non-zero on a hard failure; writes `docs/research/notes/data_audit_<date>.json`). Start from `notes/b1_scripts/b1_geometry.py` (it reuses `augment.row_rng`, `frame`, so it cannot drift). Tests: `tests/test_data_audit.py` on a 30-item fixture (property tests: inside, clearance, no overlap, determinism; a planted leak and a planted off-window mask must fail). Wire into `make preflight` before any rental (owner rule: audit coverage before spend). Libraries: pandas + scipy.stats.ks_2samp only (already in the venv); no new dependency.

R2. Fix the RL window mix before the 3.5 h run (highest value, no GPU). Today's mix has offset median 0.178 against 0.262. Options, estimates from the measured per-view shares:
 - (a) quick, config only: weight rows 0.10 centred / 0.60 shifted / 0.30 rescaled. Estimated >0.3 about 35 %, >0.2 about 62 %, S=50 share about 62 % [estimate from F4 table; verify with `mix_stats`].
 - (b) better: draw windows online. In `dataset.grpo_rows_views` (or a new `WindowSampler` dataset) call `augment.draw(item, row_rng(seed, step, item_id))` per sample, side fixed to the policy S with p=0.8 and a LADDER neighbour with p=0.2, D4 off (exam is not rotated). Needs contexts (`augment.write_context` / `render` already exist for SFT) and caches built per window: ExpertCache.build per window is the cost (about 7,341 x 3 in 2 min 11 s on the Mac with 2 procs, so on-the-fly at 32 per step is trivial on CPU, but the cache is keyed by file; add an in-memory path).
 - Keep a 10 % centred anchor (the doctors' level is already reached there; avoids forgetting).
 Gate with G9-G12 in R1 before launch.

R3. Match the exam's offset law, not only the support. Add to `augment.shift` an optional size-conditioned acceptance (accept offset if its Euclid offset/S is drawn from the exam's law, a Beta or the test empirical quantiles stored in `data/eval_views/*/manifest.json`), because uniform-in-rectangle gives large nodules little offset (F10). If R2(b) is skipped, simply oversample items with extent/S < 0.25 in the off-centre rows (hard stratum 14 % vs 9 % is already enough; check with G14).

R4. Build the test shifted view locally and freeze it. `build_eval_views --split test --out data/eval_views --procs 6`; add `--kinds shifted` to `build_eval_views.main` (KINDS filter in `build()`), removing the `rm -r` step from `rl_shifted.yaml`. Store the manifest sha256 and the `target_set_sha256` in `docs/reference/`; assert in `final_eval` that the view's sha equals the frozen one (G21). My simulation says what to expect: 2,200 items, S=50:1,997 / 100:203, offset median 0.262.

R5. Nodule-level sampling weights for RL (and nodule-level CIs in phase A). In `dataset.grpo_rows_views` add `weights = 1/sqrt(slices_in_nodule)` using `item_id.split('/')[2]` (nodule id) and `series`; give TRL a `WeightedRandomSampler` (or sample row indices in a custom sampler). Target G20 <= 25 %. In `eval/` bootstrap by patient (group_id) not by slice. Rationale: 401 test nodules; slices of one nodule are near copies (F1, F7).

R6. Decide the low-visibility rows (Q3). Add to the audit a per-item `contrast` and `hu_med` column (script has it); then either keep them (honest test) or down-weight them in RL (their reward is noise, ceiling near zero). Do this only after checking per-item doctor ceilings from `runs/r5/eval/eval_test/items.jsonl`.

R7. Verify the 84 provenance-risk items (F9) against raw DICOM: for LIDC-IDRI-0085, 0146, 0510, 0572 compute duplicated `ImagePositionPatient[2]` per series (pydicom, read-only on `data/raw`), compare with the pylidc `zvals` the builder used (`lidc.slice_index`).
