## Recommendations
1. Commit a uv lockfile for dev/CI: add `[tool.uv]` to pyproject.toml with `default-groups = ["dev"]`; move `dev` from `[project.optional-dependencies]` to `[dependency-groups] dev = [...]` (PEP 735) so `uv sync` installs it and wheels do not expose it. Keep `train`/`data` as extras. Run `uv lock`, commit `uv.lock`. CI: `uv sync --locked --extra train` (fail if stale). Keep the Docker locks as they are (separate torch/vllm pins); do not merge them into uv.lock. Add `conflicts` only if a CPU vs CUDA torch extra is added (see rec 2).
2. Torch index: add `[[tool.uv.index]] name="pytorch-cpu" url="https://download.pytorch.org/whl/cpu" explicit=true` and `[tool.uv.sources] torch = {index="pytorch-cpu", marker="sys_platform=='linux'"}` only if the CI `train` job needs it in the lock; otherwise keep `--torch-backend cpu` as now. [web: uv docs; verify syntax before use] Default: keep current flag, lowest change.
3. Make targets: `setup` -> `uv sync --locked --all-extras`; add `lock` (`uv lock`) and `lock-check` (`uv lock --check`). Keep `build` stamp logic; check scikit-build-core editable rebuild works with `uv sync` (open question Q2).
4. Add pytest-xdist to the dev group: `pytest-xdist>=3.6`. In `[tool.pytest.ini_options]` add `addopts = "-ra --strict-markers --strict-config"`, markers `gpu: needs a CUDA device and the nvcc build`, `sanitizer: run under compute-sanitizer`. Targets: `test` = `pytest -q -n auto --dist loadfile -m "not slow and not gpu"`; `loadfile` keeps module-scoped fixtures (tiny TRL model, store) on one worker. Mark the training-stack tests that build the offline TRL model with `@pytest.mark.xdist_group("trl")` and use `--dist loadgroup` if loadfile leaves workers idle. Do not use xdist for GPU tests (one device; use `-n 0`). Coverage under xdist: coverage 7 + pytest-cov already merge workers; keep `concurrency=["multiprocessing","thread"]`.
5. Hypothesis profiles: add `tests/conftest.py` block: `settings.register_profile("dev", max_examples=100, deadline=None)`; `"ci", derandomize=True, deadline=None, print_blob=True, database=None`; `"nightly", max_examples=5000, deadline=None, database=DirectoryBasedExampleDatabase(".hypothesis/nightly")`; load with `settings.load_profile(os.environ.get("HYPOTHESIS_PROFILE","dev"))`. Remove per-test `max_examples` except where a test needs a floor (the 2000/1000 oracle tests stay as `@settings(max_examples=...)` since explicit decorators override the profile). [web: hypothesis settings docs] `derandomize` in CI makes failures reproducible; nightly finds new cases and uploads `.hypothesis` as an artifact.
6. Geometry property tests to add under tests/test_geometry_props.py (library code in src/objdel/geometry): (a) polygon area equals mask area within tolerance for random simple polygons; (b) IoU symmetric, in [0,1], IoU(a,a)=1, IoU(a, empty)=0; (c) rotation/translation/scale-by-integer invariance of IoU and Betti numbers; (d) checker legality is stable under vertex rotation (start vertex) and ring reversal where the spec says it is; (e) CPU build vs CUDA build equal on the same random batch (this file's GPU variant = `@pytest.mark.gpu`). Use `hypothesis.extra.numpy` arrays and a `st.composite` simple-polygon strategy (star-shaped around a centre with sorted angles, so validity is by construction); keep 4,096 px and 1,000 vertex caps as strategy bounds. Name them in docs/testing.md section 6.
7. Ruff: keep rules; extend `select` with `"C4","SIM","PT","NPY","PERF","RUF"` incrementally (add one family per PR, run `ruff check --statistics` first). Add `ruff==0.17.1` pin kept in sync with pre-commit rev. Add `[tool.ruff.format]` and `ruff format` ONLY for src/ and tests/ (`extend-exclude` experiments, which are frozen records); first PR is a pure format commit and add it to `.git-blame-ignore-revs`.
8. Type checking: choose pyright over mypy for speed and numpy 2 stub quality; add `pyright>=1.1.390` to dev group, `[tool.pyright] include=["src/objdel"], pythonVersion="3.12", typeCheckingMode="basic", reportMissingImports="none"` for the compiled `_gpucheck` (add `src/objdel/_gpucheck.pyi` stub from nanobind `nanobind.stubgen`). Ratchet: baseline once with `pyright --outputjson` stored as a count, CI fails if the count rises; promote `geometry/`, `checker/`, `reward/` to `strict` via per-directory `# pyright: strict`. mypy only if the owner wants it (Q3). Do not typecheck experiments/.
9. pre-commit (`.pre-commit-config.yaml`, hooks pinned by rev): `ruff-pre-commit` (ruff-check --fix, ruff-format on src/tests), `pre-commit-hooks` (check-yaml, check-toml, end-of-file-fixer, trailing-whitespace, check-added-large-files --maxkb=500, detect-private-key), a local hook `no-ai-attribution` (commit-msg stage; rejects `Co-Authored-By: Claude` and `Generated with`) implementing CLAUDE.md, a local hook refusing staged paths under `data/`, `.secrets`, `runs/`, and RIGA data. Do NOT run pytest in pre-commit; `make test`/`make lint` remain the gate. Install with `uv run pre-commit install --hook-type pre-commit --hook-type commit-msg`. CI runs `pre-commit run --all-files` once (job `lint`) so the hooks and CI cannot differ.
10. CI restructure (tests.yml): split `lint` job (pre-commit + pyright, ubuntu, ~1 min) from `python` matrix; switch installs to `uv sync --locked` with `astral-sh/setup-uv` `enable-cache: true` and `cache-dependency-glob: uv.lock`; add `concurrency: {group: ${{ github.workflow }}-${{ github.ref }}, cancel-in-progress: true}`; set `HYPOTHESIS_PROFILE=ci`; run `pytest -n auto`. Keep SHA pinning. Add `timeout-minutes` to every job (only image.yml has one). Keep gates, wheels unchanged. Add a `ccache`/scikit-build `build-dir` cache keyed on cuda/ and CMakeLists hash only if wheel time is a problem (measure first).
11. GPU CI option (two tiers, both opt-in so the $3/Vast rule and cost stay controlled):
   a. `gpu.yml`: `on: workflow_dispatch` and `pull_request` with `paths: [cuda/**, CMakeLists.txt, src/objdel/checker/**, src/objdel/geometry/**]` AND a label gate `if: contains(github.event.pull_request.labels.*.name,'gpu-ci')`, `runs-on: <org GPU runner label, e.g. a T4 larger runner>` (needs Team plan, [web] ~$0.052/min => about $0.5 for a 10-minute job; verify). Steps: checkout, setup-uv, `nvidia-smi`, `bash experiments/cuda_checker/run_box.sh` (reuses the existing box chain; it already refuses RIGA data and installs nvcc and the sanitizer from PyPI), `CUDA_ARCHS=75`. Add `permissions: contents: read`, `timeout-minutes: 30`. If the owner has no paid plan, skip (a) and rely on (b).
   b. Self-hosted/Vast is the default GPU lane (rec 12). Do not register a Vast box as a persistent self-hosted runner (security: public PR code on a rented host, and the data-handling rules).
12. Nightly GPU smoke on Vast: `.github/workflows/nightly-gpu.yml` with `schedule: cron "17 6 * * *"` + `workflow_dispatch`, running on `ubuntu-latest` as an orchestrator that calls the existing policy shim: `experiments/phase2/vast/offers.sh` -> `launch.sh` (preflight first, North America only, price cap and watchdog from policy.py) -> `sync_up.sh` -> `run.sh -- bash experiments/cuda_checker/run_box.sh` -> `pull.sh` -> `teardown.sh` in an `if: always()` step, then `sweep_orphans.sh`. Needs repo secrets for the Vast key and an SSH key (no RIGA data in the bundle; run_box.sh already enforces). Cost guard: ledger cap of $0.30 per night, skip when ledger month total > $3 total budget (policy.py already holds a ledger: `experiments/phase2/vast/ledger.csv`); at a roughly $0.44 R3-class rental, 7 nightly runs would exceed $3, so default cron weekly (Sunday) plus on-demand, not nightly (owner decision, Q1). Fail the job on any nonzero exit; upload `results/cuda.json` as artifact; open an issue only via a manual step (owner rule: no GitHub mutations without ask; the workflow itself is the owner's choice).
13. compute-sanitizer job (inside run_box.sh, new function `sanitize()` and a Make target `sanitize` in the box chain):
   ```
   export PYTORCH_NO_CUDA_MEMORY_CACHING=1
   for tool in memcheck initcheck racecheck synccheck; do
     compute-sanitizer --tool $tool --error-exitcode 99 --print-limit 20 \
       --log-file build/sanitizer-$tool.log \
       $PY -m pytest -q -p no:cacheprovider -m "gpu and sanitizer" tests/test_cuda_checker_gpu.py tests/test_gpu_scoring.py ...
   done
   ```
   Add `--racecheck-report hazard` for a short log, `--show-backtrace yes`, and for memcheck `--leak-check full` and `--padding 32` (catches small out-of-bounds writes next to allocations) [web: docs list these as tool options; confirm names with `compute-sanitizer --help` on the box]. Run racecheck and synccheck on the small kernel-focused tests only (they slow runs 10-100x [estimate]); mark them `sanitizer` and keep memcheck/initcheck on the five files as today. Add a `tests/test_profile.py` assertion that all four tools appear in the chain (extend the existing one). Limit: racecheck covers shared-memory hazards only, so global-memory races in union-find need the exact-equality tests plus a repeat-run determinism test (run each kernel 20 times and compare bytes) in tests/test_cuda_checker_gpu.py.
14. Docs: update docs/testing.md sections 6-9 (add new jobs, profiles, sanitizer chain, remove the "racecheck, synccheck not run" gap when done), docs/contributing.md (uv sync, pre-commit install), add `docs/runbooks/gpu-ci.md` (how to label a PR `gpu-ci`, how nightly picks a Vast host, how to read sanitizer logs), and one ADR `docs/decisions/00N-dev-tooling.md` recording uv lock, pyright, xdist, profiles. Update CLAUDE.md "make test and make lint must pass" with the new `make check` (= lint + type + test).
15. Single entry target: add `make check` = `lint` + `types` (pyright) + `test`; add `make types`, `make sanitize` (box only), `make fmt` to run `ruff format` on src/tests as well as `--fix`. Keep `lint` meaning ruff check so existing habit and CLAUDE.md rule still hold.
16. Order of work (smallest risk first): (1) xdist + markers + Hypothesis profiles; (2) pre-commit + ruff format commit; (3) uv.lock + `--locked` CI + concurrency/timeouts; (4) pyright baseline; (5) sanitizer racecheck/synccheck + determinism test; (6) GPU workflow (manual); (7) nightly Vast weekly. Each step keeps `make test` and `make lint` green.
