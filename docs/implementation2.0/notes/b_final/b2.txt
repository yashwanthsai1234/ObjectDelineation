
The mismatch is near zero for a fresh adapter and grows as the adapter drifts (B.1 item 5). So B2 measures it
inside the B1 run, where the adapter drifts for 300 steps, and not in a short separate probe. The IS correction
does not change generation, only the loss weights, so the effect of every mode can be computed from the same
tensors in one run.

#### B2.1 Log what is lost, and what every other mode would do (device stats, no new host sync)

- `src/objdel/train/fast.py`:
  - New pure function `is_summary(logps, sampling, mask, ratio, advantages, mode, lo, hi) -> torch.Tensor`
    (float32 vector, fixed order). Active-mode part: masked count, clamped count, ratio-unit count (sequences or
    tokens), sum and max of the signed sequence log gap Σ_t (logp - sampling), sequence count, count of valid tokens
    with |gap| > 0.5, valid token count, summed length of masked sequences, summed length of kept sequences.
    Counterfactual part, computed for the same tensors whatever the active mode:
    - `cf/seqmask3_share`: sequences a `sequence_mask` with cap 3 would drop;
    - `cf/tok_clamp2_share`: tokens a `token_truncate` with C = 2 would clamp;
    - `cf/geo_0.99_1.01_share`: sequences a geometric mask [0.99, 1.01] would drop;
    - `cf/opsm_share@{0.05,0.1,0.5}`: sequences TRL's OPSM would drop at delta 0.05, 0.1, 0.5 (advantage < 0 and
      mean gap > delta, TRL's formula [code: .venv trl/trainer/grpo_trainer.py:3066-3089]);
    - `cf/opsm0.1_bigtok_unmasked_share`: valid tokens with |gap| > 0.5 that OPSM at 0.1 would keep (decides
      option D, ADR-0012);
    - `cf/seq_ratio_lt_0.1_share`: kept sequences with weight below 0.1 (down-weighted, counted nowhere today);
    - quantiles q50, q99, q99.5 of the per-sequence mean gap (q99.5 sets OPSM's delta for option E);
    - `modified_token_share`: valid tokens whose final weight differs from the raw ratio by more than 1 % (masked
      tokens included), for the active mode;
    - `ess`: effective sample size `(sum w)^2 / (N sum w^2)` of the active weights.
    Quantiles are computed on device with `torch.quantile` over the step's sequences.
  - `set_is_ratio` adds this vector to `self.is_stats` (concatenate to today's 7 sums; same min/max merge rules)
    [code: fast.py:581-602].
  - `log` emits `sampling/is_masked_share`, `sampling/is_clamped_share`, `sampling/seq_logdiff_mean`,
    `sampling/seq_logdiff_max`, `sampling/tok_absdiff_gt_0.5_share`, `sampling/masked_len_mean`,
    `sampling/kept_len_mean`, `sampling/modified_token_share`, `sampling/ess` and the `sampling/cf/*` keys, with one
    `.tolist()` as today [code: fast.py:604-616].
- No new IS mode is built now. Option E uses TRL's public `off_policy_mask_threshold`, which TRL applies inside its
  own loss; FastGRPO's `_compute_loss` calls that loss, so it works on both paths [code: src/objdel/train/fast.py:
  567-571]. The custom `sequence_geo_mask` mode (option D) is built only if `cf/opsm0.1_bigtok_unmasked_share`
  > 0.5 % over the B1 run's steps 50-300. If it is built: token ratio `exp(gap)` clamped at `hi`, times a
  per-sequence mask that is 0 when `exp(mean of the masked token gaps)` is outside `[lo, hi_geo]`; valid only on
  FastGRPO's own ratio path (TRL raises on modes it does not know [code: grpo_trainer.py:2823]), and
  `FastGRPO.__init__` raises `ValueError` if the mode is set and that path is off.
- Tests in `tests/test_train_fast.py`: synthetic tensors with planted values for every counterfactual field (a long
  sequence with a small mean gap is kept by the geo and OPSM counts and dropped by `seqmask3`; a negative-advantage

#### B2.4 Decide and clean (after B-S1, $0)

- Decision rule (ADR-0012), applied to the B1 run's counterfactual stats over steps 50-300 (the adapter has
  drifted there):
  1. Candidates: C (control), B (bf16-tis), E (bf16-tis-opsm), and A (fp16-tis) if the fp16 arm ran.
  2. Pick A if it passed Gate B2's fp16 rules AND its mean `sampling_logp_difference/mean` over steps 41-60 is at
     most half of the B1 run's over the same steps AND its s/step is at most 1.05 x the B1 run's [estimate
     thresholds: the paper reports a much larger cut, so half is a low bar].
  3. Else, among C, B and E, pick the one with the higher counterfactual ESS (median over steps 50-300). On a tie of
     0.01 or less, take the one with the lower `modified_token_share`. On a second tie, take bf16-tis (fewer moving
     parts).
  4. If B2.3b points to merge rounding, add option F as a measured arm before B3 (owner decision; ADR-0012).
  5. Build option D only under the B2.1 trigger.
- The B1 run used C, so Gate B1 has no numerics confound. If B3 uses another preset, ADR-0012 and ADR-0013 state
  that the B3-vs-B1 comparison includes the numerics change.
- Make the chosen preset the `grpo_config` default. Delete the other presets and their code paths (simple code),
  keeping `bf16-seqmask` only if it is the chosen one. Write ADR-0012 with the counterfactual table and the B2.3b
  attribution.
- **KL weight (beta).** Owner decision B.8.3 item 5. B1 keeps beta 1e-3 (as R5), so Gate B1 tests data only. For
  B3, the default is `beta = 1e-3 / r`, where r = median |A_v4| / median |A_v5| from B3.7 rule 5. That keeps v4's
  policy-to-KL balance, so the B3 A/B changes only the reward in effect. Option: beta 0.0 (Phase C's C8; with LoRA,
  TRL needs no reference copy at any beta [code: .venv trl/trainer/grpo_trainer.py:1029-1036], so beta can be raised
  later). ADR-0012 records the value. Phase C's G-C step-time gate is then computed for the chosen beta.
