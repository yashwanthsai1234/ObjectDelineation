#### B1.6 Freeze the test view; build the guard views

- `experiments/phase2/build_eval_views.py`: add `--kinds` (default all: `shifted,rescaled,rotated`; plus the new
  `edge`), so the config no longer deletes views with `rm -r`.
- New kind `edge` (the guard law). `augment.shift` draws uniformly over the admissible rectangle [code:
  src/objdel/targets/augment.py:58-71], so a "uniform" view would repeat the training law. The `edge` view draws the
  offset uniformly on the **boundary** of the admissible rectangle (the largest legal shift in a random direction),
  same side S0, same clearance and crowding checks, with its own RNG stream `row_rng(1, "edge", item_id)`. Its
  offset law has a heavier far tail than training. No row of training uses it.
- Build on the Mac after B1.0: `--split test --kinds shifted` (R5 predicts 2,200 items, offset median 0.262
  [measured: B1.md F3]); `--split val --kinds shifted,rescaled,rotated,edge`.
- **Freeze a content hash, not the manifest SHA.** The view manifest holds `reward_fingerprint`, the Python version
  and the package versions [code: experiments/phase2/build_eval_views.py:89-92], so its hash changes with harmless
  changes (another Python or OpenCV build, the B1.0 split). Content hash = SHA-256 of the newline-joined ordered
  tuples `(item_id, view.offset, view.side, image_sha256)`, plus the manifest's `target_set_sha256`.
- Store it in one place: `docs/reference/frozen_views.json`, one entry per frozen view (`lidc-test-shifted`,
  `lidc-val-edge`) with fields `view`, `items`, `content_sha256`, `target_set_sha256`, the build arguments (`seed`,
  `kinds`, `store_manifest_sha256`) and `generator_commit`.
- **One hash from A3 to the end.** Phase A3 rebuilds the test view before its rental and writes its content hash to
  the pre-rental record. B1.6 must reproduce that hash after the B1.0 rebuild, and `final_eval.json`
  `view_manifest_sha256` from A3 must equal the frozen entry. The R5 box view was never hashed [measured:
  runs/r5/eval/eval_test/final_eval.json has no view hash]. So `frozen_views.json` states: "equal to the R5 box
  view by code identity (generator files unchanged since commit 734b1ec), not measured".
- `experiments/phase2/final_eval.py`: for a frozen view, load `frozen_views.json`, recompute the content hash and the
  target-set hash, and stop with a clear message on a mismatch. A view built on the GPU host then gives the same
  hash when its windows and pixels are the same, whatever the Python or library build.
- Tests: `tests/test_p2_views.py` (content hash ignores manifest versions; changes when one offset changes; `edge`
  offsets lie on the admissible boundary and keep every doctor pixel inside with 2 px clearance);
  `tests/test_final_eval.py` (refuses a planted mismatch).

#### B1.9 Gate power check ($0, before any spend)
