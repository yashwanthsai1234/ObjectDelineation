## Findings

### F1. What the trainer does today (code, verified)
- Config: `loss_type dr_grpo, epsilon 0.2, epsilon_high 0.28, beta 1e-3, mask_truncated_completions, scale_rewards "none"`; IS keys NOT set in `grpo_config`, so TRL defaults apply: `vllm_importance_sampling_correction=True`, `mode="sequence_mask"`, `clip_max=3.0`, `clip_min=None` [code: src/objdel/train/configs.py grpo_config; TRL default: .venv/.../trl/trainer/grpo_config.py:330-347].
- Ratio code (our copy, C10 path): `diff = (logps - sampling_logps)*mask; sequence modes sum over tokens; r = exp(diff); *_mask: r outside [lo,hi] -> 0`. With `clip_min=None`, only ratios > 3 are zeroed [code: src/objdel/train/fast.py:352-363].
- The ratio multiplies the per-token loss (policy and KL) before dr_grpo normalisation by B*1536 [code: TRL grpo_trainer.py:3269-3286]. Masked sequences contribute zero gradient but stay in the group baseline.
- `use_bias_correction_kl=True` (TRL default) multiplies the KL by coef_1 [TRL grpo_config.py:353].
- Ratio uses logps from the update forward (skip_old_logps, C10) [code: fast.py:545-565].

### F2. Mismatch is real and mostly a LONG-SEQUENCE / TAIL effect
Over 750 logged steps [measured: runs/rl/train_rl/trainer/checkpoint-770/trainer_state.json]:
| metric | median | min | max |
|---|---|---|---|
| sampling_logp_difference/mean (token) | 0.0183 | 0.0094 | 0.0347 |
| sampling_logp_difference/max (token) | 3.72 | 0.23 | 25.1 |
| importance_sampling_ratio/mean | 0.823 | 0.542 | 1.036 |
| importance_sampling_ratio/min | 0.0 | 0.0 | 0.408 |
| importance_sampling_ratio/max | 2.895 | 1.78 | 3.0 |
| clip_ratio/* (all five) | 0 | 0 | 0 |
| entropy | 0.0775 | 0.0503 | 0.384 |
| completions/clipped_ratio | 0 | 0 | 0.078 |
| kl | 0.32 | 0 | 398,284 (a spike; kl max is NOT a typical value) |
- Interpretation [estimate]: mean ratio 0.82 with max pinned at 3.0 means a large share of sequences are zeroed by the `>3` rule (summed log-diff > ln 3 = 1.10). A mean token gap 0.018 x ~131 tokens = ~2.4 nats of |diff| per typical outline if gaps were one-signed; the sum can exceed 1.1 easily, and the 1,271-token tails (38 % of steps hit 1,536) exceed it almost surely. The DROPPED SHARE IS NOT LOGGED today, so it is unknown. This is the single most valuable missing metric.
- Consequence: sequence_mask discards exactly the longest / most mismatched answers; because sequence-level ratio = exp(sum diffs) grows with length, this biases training toward short outlines. Also, `clip_ratio/*`=0 means PPO clipping (incl. epsilon_high 0.28) never acts (one generation per update, ratio is 1) [measured: same file; H2_rl_math.md F3].
- Note: the logged `sampling_logp_difference` is an absolute value [code: fast.py:597]; the signed sum is what the sequence ratio uses.

### F3. FP16 fix (arXiv 2510.26788, Qi et al. 2025-10-30)
- Claim: BF16's 8-bit mantissa causes the mismatch; FP16 (10-bit mantissa) in BOTH trainer and vLLM reduces sequence log-ratio mismatch ~24x and makes plain importance-weighted PG work; TIS/MIS add "little to no benefit" and cost ~25 % (extra forward) [paper: 2510.26788; fetched via arxiv.org/html/2510.26788].
- Tested: R1-Distill-1.5B, Qwen3-30B-A3B, Qwen3-14B, Qwen2.5-Math-1.5B with LoRA r32 (BF16 collapsed ~step 600, FP16 stable), OctoThinker-3B. BF16-train + FP32-infer was stable but ~3x slower.
- Caveats from the paper: no VLM tested; no overflow statistics; VeRL showed occasional spikes; dynamic loss scaling adds a sync.
- For us: Qwen3-VL-2B is a VLM; fp16 overflow risk in the vision tower and in large activations is UNTESTED [web: no report either way found]. Our base is frozen bf16 with fp32 LoRA adapters [code: configs.py dtype() lines 83-88]; the trainer runs bf16 autocast (`_bf16()`), which is the BF16 regime the paper blames. vLLM dtype is not set in config (follows checkpoint, bf16).
- We do NOT have a measured per-step cost of the extra old-logp forward: C10 already removed it (skip_old_logps), so the paper's "25 % saving" does not apply to us.

### F4. TIS / MIS / modes (TRL 1.17.1)
- TIS = truncated IS: weight min(rho, C); from Yao, Liu et al., "Your Efficient RL Framework Secretly Brings You Off-Policy RL Training" / NeurIPS 2025 "On the Rollout-Training Mismatch in Modern RL Systems" [web: neurips.cc/virtual/2025/124259]; MIS = masked: weight 0 outside the band (DeepSeek-V3.2 style) [web: swift.readthedocs.io training_inference_mismatch].
- TRL modes: `token_truncate`, `token_mask`, `sequence_truncate`, `sequence_mask` (default), with `vllm_importance_sampling_clip_min/max` [TRL grpo_config.py:330-347].
- Bias/variance [web: yingru.notion.site Part-1, secondary]: token-level IS is biased with a bias growing with length; sequence-level untruncated is unbiased but high variance; truncation trades bias for variance. Not verified against the original text (page fetch returned empty).
- Our case: outline = 131 tokens mean, mismatch per token small (0.018). Token-level ratios (median |d| 0.018) stay near 1; the harm is from rare tokens with d up to 3.7 (max 25). So `token_truncate` (clip_max 2) keeps every sequence and caps rare tokens; `sequence_mask` throws away whole answers.
- `off_policy_mask_threshold` (DeepSeek-V3.2 eq 9: mask negative-advantage sequences whose mean per-token KL > delta, suggested 0.5) is available [TRL grpo_config.py:348]. NOTE: it uses old-vs-current logp KL, which is ~0 here (one update), so it would not catch vLLM mismatch.

### F5. Reward v4 facts (code) and H2 conclusions
- Advantage today: per-term per-group z-score with floors, weights (0.3,0.3,0.1,0.3), plus 2.0 x centred r_topo; groups with all-term spread <0.01 and one topology get 0 [code: src/objdel/reward/advantages.py:advantages_v4, spec.py REWARD_V4].
- Late groups are mostly floored (observed adv sd 0.34 < 0.53) so the objective drifted implicitly; effective weights ~6x IoU, 6x F5, 6x g_area [paper-free derivation: docs/implementation2.0/notes/H2_rl_math.md 2.2; estimate, M2 not yet measured].
- No scalar reward exists; TRL receives weight-0 loggers plus aggregator returning advantages; `sum_then_normalize` with `scale_rewards="none"` just centres (mean already 0) [code: rewards.py docstring].
- IoU_tc has no gradient for misses (IoU<0.1): 10.8 % of test images are misses [BRIEF s2]. A miss's IoU is ~0 for every answer -> group spread < floor -> advantage 0. A location term gives the group ordering.
- The scorer returns no centroid today (NUMERIC = format_ok, legal, iou_tc, iou_min, f5, g_area, topo_any, topo_freq, sig_id) [code: score.py]. The area is returned per object (`area`), but not exposed in T.

### F6. Entropy collapse
- Entropy 0.38 (max) -> median 0.0775, floor 0.05 [measured: trainer_state.json]. H2 shows this is the predicted optimum of a linear-in-policy reward with beta 1e-3 (Gibbs temperature ~1.7e-4 IoU units) [notes/H2_rl_math.md 1.1, 2.5; paper: 2505.22617].
- Cui et al.: dH ~ -Cov(log pi, A). Clip-Cov: randomly pick r*N tokens with covariance in [omega_low, omega_high], detach gradient; r=2e-4, omega 1..5. KL-Cov: top k*N tokens by covariance get a KL penalty beta=1; k=2e-3 (7B), 2e-4 (32B). Gains +1.8 / +2.0 avg points on 7B [paper: 2505.22617, via arxiv.org/html]. They used 8 updates per rollout; verl keys `loss_mode="clip_cov"|"kl_cov"`, `ppo_kl_coef=1`, `entropy_coeff=0`, clip_ratio_low/high 0.2 [web: github PRIME-RL/Entropy-Mechanism-of-RL recipe/dapo/7b_kl_cov.sh]. Exact clip_cov_lb/ub/ratio keys not confirmed from the scripts.
- TRL 1.17.1 has NO clip_cov / kl_cov loss type. Loss types: grpo, bnpo, dr_grpo, dapo, luspo, cispo, sapo, vespo. Entropy knobs: `top_entropy_quantile`, `entropy_coef` (+ `entropy_target`, `entropy_coef_min/max/delta`, the dual-ascent style controller), `delta` (two-sided clip), `epsilon_high` [code: TRL grpo_config.py:285-317, grpo_trainer.py:3228-3260].
- Clip-higher is inert for us: ratio = 1 up to numerics, `clip_ratio/*` = 0 [measured]. Clip-Cov and clip-higher both address off-policy-token gradients with ratio != 1 ... Clip-Cov's detach acts on the covariance-selected tokens regardless of ratio, so it can act on-policy (its mask is computed from logp and A, not the ratio). KL-Cov likewise.
- Caveat from H2: on centred train items collapse is convergence (train IoU 0.77 vs ceiling 0.73); entropy bonuses there lower the metric. Entropy only matters on off-centre/miss items.

## Recommendations (numbered)

### R1. Trainer-vLLM match: measure first, then pick one of three arms (cost: ~$0.5 per arm from the $3 budget, 20-30 steps each)
Do in this order; each is one config change.
1. Log the dropped share and sequence-level stats (code, no GPU): in `fast.py` `set_is_ratio` add to `is_stats` the count of masked sequences and of sequences with seq_logdiff > 0, and the share of tokens with |d| > 0.5. Log `sampling/is_dropped_share`, `sampling/seq_logdiff_mean`, `sampling/tok_gt_0.5_share`, and `sampling/dropped_by_length_q` (mean answer length of dropped vs kept). Add a unit test in tests/test_train_trl.py with a synthetic tensor (known masked count).
2. Immediate safer default (no new hardware): in `grpo_config` set
   `"vllm_importance_sampling_mode": "token_truncate", "vllm_importance_sampling_clip_max": 2.0, "vllm_importance_sampling_clip_min": None`  (plain TIS, C=2 as in Yao/Liu; C is [estimate], paper constant unverified here). Keeps every sequence, so no length bias from dropping. Also `"use_bias_correction_kl": False` (with beta 1e-3 the bias-correct term couples KL to ratio spikes; the KL spike 398,284 seen in the run suggests guarding it) [estimate; not measured].
   `is_ratio()` already supports `token_truncate` (fast.py:352-363); note `r = clamp(exp(diff), min=lo, max=hi)` with lo None works in torch.clamp.
3. FP16 arm (paper 2510.26788): trainer `bf16=False, fp16=True` in `_bf16()` override path (configs.py `_bf16`), `model_init_kwargs={"dtype": "float16"}` for the frozen base (change `dtype(lora=True)` to "float16" for GRPO only), vLLM dtype float16 via `vllm_model_impl`/engine `dtype="float16"`. In TRL 1.17.1 GRPOConfig has no `vllm_dtype` key; check `model_init_kwargs` and vLLM engine kwargs via `vllm_enable_sleep_mode` neighbours (open question Q1). Keep LoRA adapters fp32 (PEFT autocast) so dynamic loss scaling works (fp16 GradScaler requires fp32 trainable params). Gate: run 20 steps, require NaN/inf count 0, `sampling_logp_difference/mean` falls from 0.018 toward <= 0.005 and dropped share < 1 % to adopt; otherwise stay on arm 2. Vision tower under fp16 is the overflow risk; try fp16 for the LM only (vision tower stays bf16) if a NaN appears (a mixed arm is untested by the paper).
4. Decision rule (ADR): A) FP16, then IS at token_truncate C=2 only as safety net; B) bf16 + token_truncate C=2; C) keep sequence_mask (current): rejected, it keeps the length bias (F2).
5. Do not enable `off_policy_mask_threshold` for this problem (F4: it measures policy drift, which is ~0).

### R2. Reward v5 (change the definition; REWARD_V4 fingerprint changes, caches rebuild)
Definition (from docs/implementation2.0/notes/H2_rl_math.md s5, S1):
```
R_i = legal_i * ( IoU_tc_i + alpha * L_i ) + c * r_topo_i          # alpha = 0.1
L_i = 1[IoU_tc_i < 0.1] * exp( -|centroid(x_i) - centroid(V)|^2 / (2 s^2) )   # V = vote mask, s = sqrt(|U|/pi)
A_i = R_i - mean_{l!=i} R_l           # RLOO baseline; no std division, no per-term z
```
F5 and g_area: first run keeps them additive at weight 0.1 each, no z-score (the formula above shows IoU only; add `+ 0.1*f5 + 0.1*g_area` inside the legal gate). A hard-gate alternative (F5>=0.9, g_area>=0.9) is untuned [estimate; needs a lab round in experiments/phase1/lab/t_reward].
Files and exact changes:
1. `src/objdel/reward/spec.py`: new frozen `RewardV5` (keep V4 until archived by CLEAN): fields `alpha_loc: float = 0.1`, `miss_iou: float = 0.1`, `w_f5: float = 0.1`, `w_area: float = 0.1`, `c_topo: float = 2.0` (carry over, to be re-tuned since scale changed: IoU weight 1 instead of 0.3 x 20 in effective units), `group: int = 8`. `fingerprint()` already hashes the dataclass tuple.
2. CUDA scorer `cuda/gpucheck.cpp` (`score_polygons` / `score_masks`): add outputs per object `cx, cy` (centroid of the predicted mask, from the mask sums that already exist for area) and cache tables `vote_cx, vote_cy, vote_s` (centroid of vote mask and equivalent radius of the union), computed at `ExpertCache.build` (cache.py) and uploaded in `.device()`. Exact kernel: one pass of Sum x, Sum y, Sum 1 over the mask (atomicAdd or warp-per-shape reduction; the area already needs the sum). All on device (owner rule).
3. `src/objdel/reward/score.py`: add "loc" to NUMERIC and ObjectTerms (`loc = exp(-d^2/(2 s^2))` computed on device or from returned `cx, cy` with the cache's vote centroid, which is the only host arithmetic and cheap). Multi-object (RIGA): mean over objects as for iou_tc.
4. `src/objdel/reward/advantages.py`: new `advantages_v5(T, group)`: `R = legal * (iou_tc + alpha*loc*(iou_tc<miss_iou) + w_f5*f5 + w_area*g_area) + c*r_topo`; `A = R - (R.sum(1,keepdims) - R)/(G-1)`; keep dynamic sampling `drop_spread` but on R's spread. RLOO form `R_i - mean_{l!=i}R_l` equals ((G)/(G-1))*(R_i - mean R): a constant factor 8/7 vs Dr. GRPO centring. Use RLOO as written (the brief asks for RLOO) [H2 2.1]. Re-use `_topology()` unchanged; note r_topo's LOO term already uses other rollouts.
5. `src/objdel/train/rewards.py`: add "loc" to LOGGED/GATED, change AGGREGATOR to "advantage_v5"; `grpo_config` keeps `scale_rewards="none"`, `multi_objective_aggregation="sum_then_normalize"`, `reward_weights` length follows `len(LOGGED)+1`.
6. Anti-gaming tests (tests/test_reward_v5.py, using the existing oracle in tests/oracles/score_numpy.py and breakit style in tests/test_breakit_reward.py):
   - T1 location never beats a hit: any answer with IoU_tc >= 0.1 gets R >= any miss with perfect centroid: assert `0.1 + alpha*1 <= ...`? Enumerate: miss max reward = alpha*1 = 0.1 (+ F5/area terms); a hit at IoU 0.1 earns 0.1 + terms. Property test: for random pairs, `R(hit IoU=0.1) >= R(miss, loc=1)` when terms equal; this fixes alpha <= miss_iou. Condition encoded: `assert alpha <= miss_iou`.
   - T2 centroid cheating: a tiny legal speck AT the vote centroid (area below A_min) must not outscore a real miss: g_area gate (0 for tiny) must remove the term; test that speck R < legitimate nearby-correct-size miss R. Needs `loc` multiplied by `g_area >= 0.9` or by size filter: define `L_i := ... * (g_area>=0.5)`.
   - T3 spread-out/huge polygon: a huge shape centred on vote centroid (covers U) has high IoU? No: IoU low but loc=1; g_area kills it (A > A_max). Test it.
   - T4 two components: centroid of a two-blob shape lying between them while neither overlaps; loc high, IoU 0. Require legal AND the answer to have exactly `topo_any>0`; if still exploitable, define location on the nearest-component centroid. Test documents the residual (xfail marker with comment if not fixed).
   - T5 monotonic: for fixed shape shifted by d pixels, R decreases monotonically in d while IoU<0.1.
   - T6 gate: illegal answer gets R = 0 (even with centroid exact).
   - T7 RLOO unbiased: for a group, `A_i` sums to 0; scaling the group's rewards by 5 scales A by 5 (no std division).
   - T8 floors/drop_spread: group of equal rewards -> A = 0 (no NaN).
   - T9 centroid exact vs a numpy oracle on 200 random masks (CUDA vs host, within 1e-4 px).
7. Lab round before use (measured on the existing runs, no GPU needed): recompute v4 vs v5 advantages on rl.json answers saved in `runs/rl/train_rl` (answers parquet if present; else a new 16-step probe at ~$0.2). Report: share of miss groups with nonzero advantage (v4 ~0 by F5, v5 expected > 0), correlation of A_v4 and A_v5 on hit groups (expected high), advantage sd.
8. Keep `G = 8` (H2 2.7).

### R3. Entropy collapse controls (order by cheapness, on the shifted-views run)
1. DO NOT rely on clip-higher: `clip_ratio` is 0. Leave `epsilon_high` 0.28 (harmless) but state in docstring that it is inactive; if we ever run >1 update per generation it activates.
2. Measure per offset bucket before touching: log entropy per window kind (centred / shifted / rescaled) from `trainer.log` using `key` suffix; add M3 diversity metric (mean in-group IoU between answers) via `TRLReward` `log_metric("div/in_group_iou")`.
3. Cheapest available knob in TRL 1.17.1: entropy controller:
   `"entropy_coef": 0.0 -> use "entropy_coef": 0.001, "entropy_target": 0.06, "entropy_coef_min": 0.0, "entropy_coef_max": 0.01, "entropy_coef_delta": 0.0005, "top_entropy_quantile": 0.2` (bonus applies only below target; top_entropy_quantile restricts the loss to high-entropy tokens). Caution: `top_entropy_quantile < 1` disables our `_prepare_inputs` length-sorted micro-batching path (fast.py requires `top_entropy_quantile >= 1`), costing speed [code: fast.py:`_prepare_inputs`]. So use ONLY `entropy_coef`/`entropy_target` without `top_entropy_quantile`. Values are [estimate]; entropy target 0.06 sits at the observed floor 0.05-0.08.
4. Clip-Cov / KL-Cov are NOT in TRL 1.17.1 and have no library; implementing in `fast.py` is ~25 lines: after TRL computes `per_token_logps` and `advantages`, compute `cov = (logp - logp.mean()) * (A - A.mean())` over the micro-batch tokens (mask), Clip-Cov: select r*N random tokens with cov in [1, 5], zero their per-token loss. r=2e-4 (paper) but paper used 8 updates; with N ~ 16*131 tokens per micro-batch the count rounds to 0. Use r = 2e-3 per generation batch (`N` = all completion tokens of 256 answers ~ 33,500 -> ~67 tokens) [estimate]. Defer: add only if R3.3 plus the dropped-share fix leaves entropy < 0.05 AND shifted-view validation is flat. Entropy collapse on centred items is convergence (H2), so the pass criterion is held-out shifted IoU, not entropy.
5. Prefer fixing the objective over regularising (H2): v5 plus training on shifted/rescaled windows creates reward variance where the policy is still wrong; then entropy stays alive there without a bonus.

### R4. Verification gate for one combined probe (budget ~$1.0 of $3)
Arms: (i) bf16 + sequence_mask (control, current), (ii) bf16 + token_truncate C=2, (iii) fp16 + token_truncate. 20 steps each on rl_shifted data, same seed. Report: dropped share, mean |logp diff|, reward, NaN count, s/step. Preflight per owner rule. Then the v5 run only after R2.7.
