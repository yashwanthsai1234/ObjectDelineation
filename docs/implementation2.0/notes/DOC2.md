## Findings
1. Material for MkDocs entered maintenance mode 2025-11-05; feature work ended; critical/security fixes until 2027-05-05 [web: squidfunk.github.io/mkdocs-material/blog/2025/11/05/zensical/]. Material 9.x still works and is the safe choice for a repo like this today.
2. Zensical (MIT, same team) reads mkdocs.yml and builds supported Material projects; feature parity incomplete, only a subset of plugins; its 0.1 "dependable release line" was dated 2026-11-05 [same source]. mkdocstrings author is joining Zensical to build docstring API reference there, but the article does not say mkdocstrings works in Zensical today [same source]. I could not verify Zensical mkdocstrings status [unverified].
3. Ruff D rules are the pydocstyle replacement (pydocstyle unmaintained), off by default, selectable per rule, with a `convention` setting [web: search results; ruff settings docs not fetched in full]. Ruff has a pydoclint group (DOC); I did not confirm which DOC rules are stable vs preview [unverified: check the preview marker in docs.astral.sh/ruff/rules].
4. interrogate measures docstring presence as a percentage with `--fail-under`; ruff D100-D107 flag each missing docstring [web: search results]. Common split: ruff for style, interrogate for a coverage number.
5. NeurIPS 2025: paper checklist mandatory, desk reject without it, answers Yes/No/NA with justification, not counted in page limit; code release not required but a reasonable reproducibility path is [web: neurips.cc CallForPapers/PaperChecklist, search snippet]. Critics: self-reported, checks intention not execution [web: arXiv 2605.08586, snippet only]. I found no official MICCAI 2025 checklist [unverified].
6. Hugging Face model card template: Uses (Direct, Downstream, Out-of-Scope), Bias/Risks/Limitations, Training, Evaluation sections [web: huggingface.co/docs/hub/model-card-annotated]. Origin papers: Mitchell et al. arXiv 1810.03993 (model cards), Gebru et al. arXiv 1803.09010 (datasheets) [from my knowledge; not fetched].
7. CITATION.cff: example uses cff-version 1.2.0; GitHub renders it on the repo page with a BibTeX snippet when on the default branch [web: citation-file-format.github.io]. Validator tool not confirmed on that page; cffconvert validate is the usual one [unverified].
8. lychee-action v2 checks links in Markdown/HTML, supports caching to avoid rate limits; versions before 2.0.2 have CVE-2024-48908 [web: search results]. Pin by SHA like existing workflows.
9. Diataxis (tutorials, how-to, reference, explanation) is the dominant doc structure; existing docs/ folders map cleanly (see rec 2) [knowledge; not re-fetched].

## Recommendations
1. Tooling: MkDocs + Material 9.x + mkdocstrings[python]. Add dev extra `docs = ["mkdocs-material", "mkdocstrings[python]", "mkdocs-gen-files", "mkdocs-literate-nav"]`, pin exact versions (repo pins everything). Keep mkdocs.yml Zensical-compatible (no exotic plugins) so a later swap is a one-line change. Re-check Zensical + mkdocstrings in 2027 before May 5.
2. Diataxis map, no moves needed: tutorial = docs/getting-started.md; how-to = docs/guides/*, docs/runbooks/*; reference = docs/reference/* + generated API; explanation = docs/architecture/*, glossary, research. Add a `nav:` in mkdocs.yml with these four headings. Exclude docs/research/*.pdf and research2.0 from nav via `exclude_docs`.
3. API reference auto-generated: docs/gen_ref_pages.py using mkdocs-gen-files to walk src/objdel and emit `::: objdel.<module>` pages; mkdocstrings config `handlers.python.options: docstring_style: google, show_source: false, members_order: source`. Only the C++ extension objdel._gpucheck is not introspectable: document it by hand in docs/reference/cuda-engine.md (already exists).
4. Docstring style: Google style (short summary line + Args/Returns only where types or units are not obvious; units and grid conventions like 0-1000 are the valuable part). Enforce in pyproject: `select += ["D"]`, `[tool.ruff.lint.pydocstyle] convention = "google"`, ignore D105, D107, D203, D213; per-file-ignores `tests/**` and `experiments/**` = ["D"]. Start with `D100-D103` only on src/objdel, ratchet later.
5. Docstring coverage gate: add `interrogate` to dev extra; `[tool.interrogate] fail-under = 75` now (current 75 %), raise to 95 after the 80 missing docstrings are written; options ignore-init-method, ignore-magic, ignore-private, exclude tests/experiments. Make target `docs-cov`. Writing the 80 missing docstrings is a CLEAN/DOC task; list them with `interrogate -vv src/objdel`.
6. Docs build in CI: add job `docs` in .github/workflows/tests.yml (ubuntu-latest, SHA-pinned actions as existing): `uv pip install -e ".[docs]"` using the CPU-only build (no torch needed: mkdocstrings uses static analysis via griffe, so torch/trl imports do not run; verify once). Run `mkdocs build --strict` (warnings become errors: broken nav, bad cross-refs, unresolved `:::` targets). Add Make targets `docs` (build strict) and `docs-serve`. Deploy to GitHub Pages only from main, later; optional.
7. Link check: lychee-action v2 pinned by SHA, args `--no-progress --cache --max-cache-age 1d --exclude-path docs/research docs README.md`, plus `.lychee.toml` with `accept = [200,429]`, excludes for localhost and private HF repo URLs (svenk029/objdel-sft returns 401/404 without auth). Run on PRs touching *.md and weekly cron; weekly cron failure must not block merges. Offline internal-link check is already covered by mkdocs --strict.
8. Docs tests (cheap, in tests/): (a) test that every `docs/reference/*.md` code span naming `objdel.x.y` resolves via importlib; (b) test that every ADR file has Status/Date/Context/Decision/Consequences headings and is listed in decisions/README.md; (c) run `python -m doctest`/pytest `--doctest-glob` on short examples in docs/reference/output-format.md; (d) test that config keys documented in docs/reference/configs.md equal fields of the config dataclasses in src/objdel/train/configs.py (drift test). These reuse the repo's existing preference for tests over prose.
9. ADRs: keep the current numbered files; add a template docs/architecture/decisions/_template.md (Status, Date, Context, Decision, Alternatives, Consequences, Supersedes) and a rule: a PR that changes a pinned version, reward term or CUDA contract must add or supersede an ADR. Never edit an accepted ADR except Status.
10. Model card: add docs/model-card.md as the source, published as README.md of HF repo svenk029/objdel-sft (private) through `huggingface_hub.ModelCard`. Sections: Model details (Qwen3-VL-2B + LoRA, adapter name, training stack pins), Intended and out-of-scope use (research only, not diagnostic), Training data and procedure (SFT then GRPO, train views), Evaluation (test IoU 0.645, F 0.816, legal 0.994, doctor ceiling 0.732 with the json path), Limitations (10.8 % misses; shifted crops; LIDC and RIGA only), Bias/risks, Citation. Numbers must be filled by a script from runs/r5/eval/eval_test/final_eval.json so card and measurement cannot drift (add `scripts`/Make target `card`).
11. Data card (datasheet style, Gebru 1803.09010): docs/reference/data.md gets sections Motivation, Composition (counts, splits, raters), Collection/licence (LIDC-IDRI TCIA licence, RIGA terms), Preprocessing (crops, 0-1000 grid, shifted/rescaled views), Uses, Known issues. Do not redistribute data; data/ stays git-ignored.
12. Reproducibility checklist: docs/reproducibility.md modelled on the NeurIPS checklist items (claims, limitations, compute, seeds/error bars, code, data, licences). For each item: Yes/No/NA, evidence path, command. Concrete entries: environment locks (pyproject pins, uv), `make test`/`make cov`, preflight command, run configs under experiments/phase2/configs, GPU type and hours/cost per run from runs/ and ROADMAP, bootstrap CIs from final_eval, target-set hash. Add a `make repro-check` that asserts each referenced path exists.
13. CITATION.cff at repo root: cff-version 1.2.0, message, type: software, title, authors, version (must match pyproject `version`), date-released, license, repository-code. Add a test comparing CITATION version with pyproject version; validate with `cffconvert --validate` (verify command) in the docs job. Add a Citation section to README.
14. Changelog: keep docs/changelog.md in Keep-a-Changelog format; Make target does not generate it (commit messages are free-form), so require manual entry per merged phase.
15. Single process (CONTRIBUTING + PR checklist): a change to src/objdel behaviour must (1) update docstring, (2) update docs/reference page if a key, field or format changed, (3) add ADR if a decision, (4) update changelog; CI enforces: ruff D, interrogate threshold, mkdocs --strict, lychee, docs tests. Add `.github/pull_request_template.md` with these boxes (no AI attribution lines per CLAUDE.md).
16. Order of work: (a) mkdocs.yml + gen_ref_pages + CI docs job (strict) ; (b) ruff D100-D103 + interrogate at 75 %; (c) write missing 80 docstrings, raise gate; (d) CITATION.cff, model card script, data card, reproducibility page; (e) lychee; (f) docs tests.
