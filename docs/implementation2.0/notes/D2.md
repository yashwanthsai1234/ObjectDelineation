## 2. Findings

### 2.1 Connected-component labelling (CCL)
F1. State of the art on GPU is still the Allegretti/Bolelli/Grana line: BKE (2x2 blocks + Komura equivalence) and BUF (block union-find), 2D 8-conn and 3D, measured on YACCLAB [paper: Allegretti et al., IEEE TPDS 2018, iris.unimore.it/.../2018_TPDS_Optimized_Block_Based_Algorithms...pdf; the PDF was unreadable by WebFetch, only the abstract topics were confirmed] [web: iris.unimore.it]. My web search found no 2025-2026 GPU CCL paper that beats it [web search, negative result, not proof].
F2. NPP `nppiLabelMarkersUF_*` implements the Chen et al. union-find (arXiv 1708.08180: local merge, boundary analysis, link; reported ~5x/3x/1.3x faster than label-equivalence, parallel UF, line-based UF) [web: docs.nvidia.com/cuda/archive/11.2.1/npp/group__image__filter__label__markers.html] [paper: 1708.08180]. 8-conn is `nppiNormInf`, 4-conn `nppiNormL1` [web: NPP 10.2 docs]. It had wrong-result bugs in CUDA 11.4 (fixed 11.5) [web: forums.developer.nvidia.com threads 184854, 188097]. CUDA 13 behaviour not verified [unverified].
F3. CV-CUDA `cvcuda.label` exists (since v0.5.0): 2D and 3D, optional count and per-label stats (7 per label 2D, 9 3D), background-label tensor [web: cvcuda.github.io/_exhale_api/group__NVCV__C__ALGORITHM__LABEL.html via search; direct fetch of python page returned 404]. Release notes mention "4-way foreground and 8-way background" wording [web search snippet, unverified]. This may be the opposite of the repo's (8 fg, 4 bg) pairing [code: H1:35-36]. Must be tested.
F4. cuCIM `cucim.skimage.measure.label(connectivity=1..ndim, background=0, return_num)` is nD, skimage-compatible [web: docs.nvidia.com/cucim/latest/api/]. cuCIM also ships `euler_number(connectivity)` (2D: objects minus holes; 3D: objects plus holes minus tunnels), `regionprops_table(batch_processing=True)`, `perimeter` [web: same]. License Apache-2.0, pip `cucim-cu12` / `cucim-cu13` [web: github.com/rapidsai/cucim]. Label-id order and determinism are not documented [web: CuPy `ndimage.label` page also silent, and warns "may synchronize the device"].
F5. Playne-Hawick label equivalence (the repo's current invariant, atomicMin retry [code: H1:78]) is the baseline all of the above beat; YACCLAB is the benchmark. Run-based warp-per-row (HA4/FLSL, Hennequin/Lacassagne DASIP 2018) matches the repo's bit-word layout [code: H1:288-295]. A third-party `bkeccl` package on PyPI exposes BKE directly [web: pypi.org/project/bkeccl, snippet only; maturity unknown].
F6. Doctrine from H1: all outputs are integers uniquely defined by the input, so any correct CCL returns identical component partitions; only label NUMBERS differ. The repo needs min-index labels only if ring order depends on them [code: H1:11 F11, 35-41].

### 2.2 Contour / ring tracing
F7. TRUCO (arXiv 2610.37297, Munoz-Salinas, Romero-Ramirez, Marin-Jimenez, v1 2026-10-27, v2 2026-11-01, CC BY 4.0): lock-free parallel contour extraction, output identical to Suzuki-Abe (contours, order, hierarchy), horizontal stripes, one thread each, tracing decoupled from hierarchy, no label image with contour numbers. Claims "several times faster" than sequential methods even single thread; no numbers in the abstract [web: arxiv.org/abs/2610.37297]. It is MULTI-CORE CPU, not GPU. Stripe-per-thread with ownership rules does not map to 100 k GPU threads on a 512x512 mask. Useful only as (a) a CPU reference/fallback that matches Suzuki-Abe order, (b) an idea: hierarchy rebuilt from one reference per contour [estimate: relevant to our closed-form ring start, H1:35-38].
F8. The repo's own plan (closed-form ring start from CCL labels, only corner order needs list ranking, O(E) not O(E log E)) is already work-optimal and exact [code: H1:35-41, 186-195]. No library exposes crack-edge (8,4) ring tracing on GPU. cuCIM has `find_contours` (marching squares, float contours) per its API list but I could not confirm its entry [web: unread part of cuCIM API page]; marching squares output is not the exact integer crack-edge ring the checker needs.

### 2.3 Exact EDT
F9. cuCIM `distance_transform_edt(image, sampling, return_distances, return_indices, block_params, float64_distances)` uses the parallel banding algorithm PBA+; indices may differ from SciPy on ties; `float64_distances=True` to match SciPy; `sampling` handles anisotropic voxels (CT) [web: docs.nvidia.com/cucim/latest/api/]. Added in cuCIM 22.10 [web: pypi.org/project/cucim/22.12.0 snippet]. CuPy also has `cupyx.scipy.ndimage.distance_transform_edt` [web: docs.cupy.dev]. Whether PBA+ is exact (not approximate) for all inputs: PBA+ is published as exact [estimate, from memory of Cao et al. 2010; not re-verified this session].
F10. H1 recommends a separable Meijster/Felzenszwalb EDT on integer squared distances so values equal SciPy float32 bit for bit [code: H1:388-394]. Current use: eval NSD per sample and offline cache EDT (CPU, once per item, acceptable) [code: H1:372-377].

### 2.4 Betti / Euler / topology
F11. TopoGPU (arXiv 2610.10959, Wang, Wagner, Chowdhury, Chen, v1 2026-10-07, TPAMI-accepted): GPU streaming pipeline for persistence diagrams of 2D/3D cubical complexes; GPU kernels build Morse boundaries, the CPU does matrix reduction; avg 53.24x, max 198.01x over Cubical Ripser; open source [web: arxiv.org/abs/2610.10959]. It computes full persistence; we need only b0, b1 (and b2 in 3D) of one binary level set. Overkill and has a CPU step (owner rule: CPU only where unavoidable). Use as a cross-check oracle, not as production.
F12. For binary images, b0 = CCL(8) count, and b1 = b0 - Euler number; the Euler number is a sum over 2x2 windows (bit-quads), all device-local [code: H1:44-45]. cuCIM `euler_number` offers the same on GPU but returns one scalar per image, not per component [web: cuCIM API]. Our scorer needs per-component holes, so the bit-quad kernel stays custom.

### 2.5 Libraries
F13. NVIDIA Warp 1.x: Apache-2.0, Python JIT kernels, CUDA needs Turing (sm_75)+ and driver R580+ for default CUDA 13.4 wheels; supports last two CUDA majors; no CCL, EDT or morphology functions listed; mesh, hash grid, volume and marching-cubes examples exist; sm_120 not named, PTX JIT forward-compat "may" cover it [web: github.com/NVIDIA/warp, nvidia.github.io/warp/v1.19/user_guide/compatibility.html]. Relevant for the later 3D-voxel/Physical-AI phase (meshes, SDF), not for 2D CCL.
F14. CCCL (CUB/Thrust/libcudacxx): CCCL 3.4 notes faster `cub::DeviceScan` on Blackwell; 3.5 adds per-architecture policy selectors; Python `cuda-cccl` (`cuda.compute`: reduce, scan, sort) on PyPI, CUDA 12/13 [web: newreleases.io/project/github/NVIDIA/cccl/release/v3.4.0, v3.5.0; pypi.org/project/cuda-cccl]. Version numbering conflict seen (0.5.1 vs 1.1.x) [unverified]. CUB `DeviceScan`, `DeviceRadixSort`, `DeviceSegmentedReduce`, `DeviceSelect` are the right buy for list ranking prefix sums, ring compaction and per-ring totals.
F15. Triton: PyTorch 2.7.0 first stable with native sm_120 (CUDA 12.8 wheels, Triton 3.3) [web: docs.salad.com pytorch-rtx5090 guide, third-party]. Triton fits dense tile math (batched point-in-polygon, per-pixel scoring) but not irregular union-find/pointer chasing. I found nothing on Triton atomics performance for union-find [unverified].
F16. No NVIDIA library gives: exact crack-edge ring tracing, per-component Euler/holes, or warp-per-shape exact polygon validity. These stay custom (matches H1).

## 3. Build-vs-buy per function
| Function | Today | Buy candidate | Verdict | Why |
|---|---|---|---|---|
| 2D CCL, fg 8-conn | row-per-thread, byte pixels [H1:41] | cuCIM label (conn=2), NPP UF (NormInf), CV-CUDA label, BKE/bkeccl | BUILD run-based warp-per-row on bit words (H1 plan) as the product; BUY cuCIM `label` as parity oracle in tests and as first quick win for eval-only paths | Our data is bit words; library needs byte/int input (8x copy) and gives undocumented label ids; exactness test needs an independent implementation |
| Bg 4-conn CCL | 4 labelings [H1:F4] | cuCIM label(conn=1) on inverted mask | Remove the pass: use per-component Euler (bit-quad) | Fewer passes beats faster passes |
| 3D CCL (26-conn fg, 6-conn bg) | scipy CPU [H1:F10] | cuCIM label (nD), CV-CUDA 3D | BUY cuCIM for phase 3D prototype; revisit BUF/BKE 3D if slow | 3D is future, library is nD already |
| Ring tracing (exact crack-edge) | slot-grid pointer jumping [H1:F2] | none (TRUCO CPU; cuCIM find_contours is float marching squares) | BUILD (closed-form start + compaction + CUB scan/sort) | No GPU library gives exact integer rings |
| Compaction, prefix sums, sort, segmented reduce | custom | CUB via CCCL | BUY (CUB) | Standard, tuned for Blackwell |
| Euclidean DT (eval NSD, cache) | scipy CPU | cuCIM `distance_transform_edt` (PBA+, `float64_distances`, `sampling`), CuPy ndimage | BUY first, with bit-parity test vs SciPy; fall back to custom integer Meijster only if ties or float32 mismatch break checks | Library is exact-capable and anisotropic-ready; offline cache has no latency need |
| Betti b0, b1 | CCL + Euler on GPU | cuCIM `euler_number`; TopoGPU | BUILD per-component bit-quad Euler; use TopoGPU only as research oracle | Per-component output and no CPU step |
| 3D Betti b0,b1,b2 | scipy CPU | cuCIM `euler_number` 3D + label | BUY for prototype, BUILD cell-attributed chi_k if per-object needed [H1:80] | |
| Per-object stats (area, bbox) | custom | cuCIM `regionprops_table(batch_processing=True)` | Optional | Our totals are exact integers in custom kernels |
| Dense tile math | n/a | Triton | Skip | Irregular kernels dominate |
| Mesh/SDF/voxel (phase 3D) | none | Warp | Evaluate later | Out of scope for D |

## 4. Recommendations (numbered)
1. Keep BUILD for the rasterized-mask-to-rings pipeline in `cuda/gpucheck.cpp` (run-based CCL on bit words, closed-form ring starts, per-component bit-quad Euler). Do not adopt TRUCO for GPU; optionally keep a CPU reference in `tests/` that matches Suzuki-Abe order (cv2.findContours) to verify ring ORDER, since F11 in H1 says ring order is a convention.
2. Add an oracle test `tests/test_ccl_oracle.py` (gated by `pytest.mark.gpu` and `importlib.util.find_spec("cucim")`): compare partitions (not label ids) of the CUDA CCL against `cucim.skimage.measure.label(mask, connectivity=2)` and `scipy.ndimage.label(mask, structure=np.ones((3,3)))` on random masks (density 0.1-0.9, 64..512 side, 1000 cases). Compare background with connectivity=1. Add `cucim-cu13` to an optional `[gpu-test]` extra only, not runtime.
3. Replace CPU EDT with cuCIM in `src/objdel/eval/metrics.py` (`_surface` NSD) via a thin `geom/edt.py`: `cucim.core.operations.morphology.distance_transform_edt(x, sampling=spacing, return_distances=True, float64_distances=True)`. Gate with a test that max |diff| vs `scipy.ndimage.distance_transform_edt` is 0 on 1000 random masks; if not 0, write the integer separable kernel (H1:388-394). Keep `reward/cache.py` EDT offline until the test passes.
4. Use CUB (CCCL) for any new compaction/scan/sort in the ring tracer. Pin CCCL version to the one shipped with the CUDA 13 toolkit used in `cuda/docker_check.sh` (CUDA 13.0) and run `nvcc` on `-gencode arch=compute_120,code=sm_120` (already in `CUDA_ARCHS="80;86;89;90;120"`).
5. Do not adopt NPP or CV-CUDA label for production: unclear connectivity pairing (F3), historical NPP bugs (F2), byte input. Test CV-CUDA only if a one-line pairing check shows (8 fg, 4 bg) is available.
6. For TopoGPU: add to `docs/research/notes/` as an oracle for 3D persistence when the 3D phase starts; do not depend on it in the library (CPU matrix reduction, F11).
7. GPU CI: add `.github/workflows/gpu.yml` with `runs-on:` a hosted RTX 5090 runner (StarSling label, F18) triggered by `workflow_dispatch` plus label `gpu` on a PR, running `make cuda` + `pytest -m gpu -x` + `compute-sanitizer --tool racecheck/memcheck/synccheck` on the CCL and ring kernels (compute-sanitizer catalog skill, F1). Config keys: `timeout-minutes: 10`, `concurrency: gpu-ci` to cap spend at about 0.15 USD per run (F22). Keep the CPU `docker_check.sh` compile matrix on every PR.
8. If hosted-runner cost or trust is a problem, fallback is a self-hosted ephemeral runner on a Vast North America RTX 5090 started by hand before a release (owner rule: preflight before every rental); never attach it to a public repo (F20).
9. Before writing any of the above, run a 20-line spike (no spend; local or the next paid GPU session) printing `cucim.skimage.measure.label` timings vs the current CUDA CCL on 512x512 masks, to decide whether the custom run-based CCL pays off. Gate: build custom only if the library is slower than 2x or its time includes a host sync.
