### F3. Medical
- Qwen medical VQA (card): SLAKE Qwen3-VL-2B 61.1, Qwen3.5-2B 74.4/67.5, Qwen3-VL-4B 65.9, Qwen3.5-4B 76.1 (last column read); PMC-VQA 42.4 / 48.8 / 48.4 / 55.5 [measured: Qwen cards]. VQA, not localisation.
- MedGemma-4B and Lingshu-7B cannot localise: SLAKE box IoU 0.05 and 0.07, below a fixed centre box 0.10 [paper: arXiv 2604.27720, via docs/implementation2.0/notes/E_vlm_seg_sota.md]. MedGemma's medical pretraining does not help outlines; gated licence adds friction.
- No small VLM has published LIDC nodule outline numbers. Medical gain must come from our own SFT+RL.

### F4. Polygon/segmentation as text
- Qwen-family: 0-1000 box/point grid is native, so our 0-1000 polygon JSON matches pretraining (no new tokens). SimpleSeg (arXiv 2601.19228) shows polygon text + RL (GSPO) works on Qwen2.5-VL and Kimi-VL.
- Florence-2 (loc tokens, polygon output) and PaliGemma (loc + VQ seg tokens) have non-text mask formats; PaliGemma masks are 64x64 in box: too coarse [paper: 2412.03555 via SP].
- InternVL3.5 uses 0-1000 style but different conventions; MiniCPM-V and Gemma 4 grounding weak or format differs.
- LFM family: our repo already tested LFM2.5-VL (max_completion 1024 because 5.2 vs 8.2 tokens/vertex; vLLM colocate OK) [code: src/objdel/train/configs.py:17-31]. Different tokenisation changes outline token budget.

### F5. Stack fit (pinned: torch 2.14.1, transformers 5.20.1, trl 1.17.1, peft 0.21.2) [code: pyproject.toml:19-25]
- FastGRPO (shared-prefix forward, RopeCache, ImageMemo, vision cache) is written for Qwen3-VL (3-D rope, get_rope_index) [code: src/objdel/train/fast.py:1, :295]. Qwen3-VL-4B uses the same classes: expected drop-in (config change only; hidden size differs). Qwen3.5 (hybrid Gated DeltaNet + gated attention, `Qwen3_5ForConditionalGeneration`) breaks shared-prefix forward and attention-based RopeCache assumptions: linear-attention recurrent state cannot share a KV prefix the same way. Needs vLLM >= 0.17, flash-linear-attention, causal-conv1d; LoRA must target DeltaNet projections; reported flash-attn2+packing loss-0 problem; vLLM issues vllm#36275, ms-swift#9800 [web: prior survey + search 2026-11-08]. [estimate: 1-2 days of patch work plus new risk, before any quality gain].
- LFM3-VL-2B: `custom_code`, vLLM support exists per card, SGLang in review; TRL documented by vendor. New conv+attention stack, vendor-only numbers, licence gate. High integration risk.
- hf-mem: Qwen3-VL-4B weights 8.9 GB bf16. LoRA + colocated vLLM sleep on 32 GB: plausible; 2B run currently fits. [estimate; unmeasured, needs a preflight on the 5090].
- Cost: 4B roughly doubles per-step compute vs 2B (23.6 s/step at 2B [measured: README/commit be52b1c message]); with $3 GPU budget a 4B RL run is much shorter. [estimate]

## Recommendations
1. Do not change the model for the B1 data-fix run. Train Qwen3-VL-2B with `train_rl --train-views` (plan `experiments/phase2/configs/rl_shifted.yaml`). Reason: root cause is data; changing both confuses attribution.
2. Add `"qwen3-vl-4b": "Qwen/Qwen3-VL-4B-Instruct"` to the model map in `src/objdel/train/configs.py` (next to line 73), add it to `MAX_COMPLETION` (1536), `_LORA` and `_GRAD_CKPT` sets (lines 75-77). No other code expected to change; verify `fast.py` shape assumptions (hidden size, layer count, PAIR constant at line 81 is 2B-specific: recompute).
3. Gate 4B on a measured preflight (no spend beyond preflight rule): 20-step probe on the 5090 recording peak GPU memory with vLLM colocate sleep, `s/step`, and IS-ratio stats; accept only if peak < 30 GB and step time <= 2.2x the 2B step. Run `uvx hf-mem --model-id Qwen/Qwen3-VL-4B-Instruct --experimental --max-model-len 3072` first (9.48 GB at 4096).
4. Compare 2B vs 4B on the same shifted validation split with nodule-level bootstrap CIs (Phase A tooling). Choose 4B only if held-out IoU gain exceeds the CI and budget remains.
5. Park Qwen3.5 and LFM3: re-evaluate only if vLLM and TRL ship hybrid-model colocate+LoRA support without patches. If re-evaluated, add LoRA targets for DeltaNet projections and disable shared-prefix forward for that model.
6. Do not use MedGemma/Lingshu: measured localisation worse than a centre box.
7. Keep polygon-as-text with the 0-1000 grid (SimpleSeg precedent); keep `max_completion_length` per-model in `MAX_COMPLETION`, and re-count outline tokens per tokenizer (script: A1 token probe) before using any non-Qwen model.
8. Doc: record decision as an ADR in `docs/decisions/` (keep 2B for B1; 4B as conditional upgrade; reasons F2-F5).

## Open questions
- Does 4B + vLLM colocate + LoRA fit 32 GB at 16x16 micro-batches? (unmeasured)
- Real gain of 4B on LIDC outlines: RefCOCO gain (3.4 points) may not transfer to nodules.
- LFM3-VL-2B numbers are vendor-only; independent evaluation absent. Licence acceptable for owner's use? (revenue threshold $10M, probably fine for research.)
- Qwen3.5 vLLM/TRL support state in vLLM current release was not verified against our pinned stack (search found only issues, no confirmation of merged fixes).
- Gemma 4 12B (82.2) and Qwen3.5-9B exceed 4B; out of scope.
