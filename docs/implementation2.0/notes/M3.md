## Findings

### A. What small VLMs the RL segmentation / grounding papers used (and 2B-to-4B evidence)

1. SimpleSeg (2601.19228, polygon text, SFT then GSPO) used only Qwen2.5-VL-7B and Kimi-VL (2.8B active MoE). It has no 2B vs 4B comparison. [paper: 2601.19228 sec 4.1]
   Kimi-VL (2.8B active) is level with the 7B Qwen model on RefCOCO gIoU (refCOCO val 76.9 for Kimi-VL after RL; the 7B Qwen row is lower on the same table). So active size, not total size, does not decide polygon quality. [paper: 2601.19228 Table 1]
2. EGM (2601.13633, Qwen3-VL-2B/4B/8B-Thinking, SFT with reasoning traces then GRPO) is the cleanest measured 2B vs 4B vs 8B ladder. RefCOCO-family average accuracy [paper: 2601.13633 Table 2]:
   - Qwen3-VL-2B-Instruct 84.2 | 4B-Instruct 87.3 | 8B-Instruct 88.3
   - Thinking base: 2B 83.6 | 4B 87.2 | 8B 87.8
   - After EGM (SFT+RL): 2B 89.6 (+6.0) | 4B 91.0 (+3.8) | 8B +3.6 (value not copied here)
   - The 2B to 4B gap shrinks from +3.6 (thinking base) / +3.1 (instruct) to +1.4 after RL. Training closes most of the size gap. Their own words: the 2B and 4B EGM models beat 8B-Thinking by +1.8 / +3.2.
   - EGM says 52.8 % of small-model failures are "COMPLEX-PROMPT" (language understanding), not vision. [paper: 2601.13633 Table 1] Our prompt is fixed and short, so this failure type is mostly absent for us.
3. Topo-R1 (2603.13054, GRPO after SFT, topology anomaly localisation with Betti labels) ran InternVL-2.5-2B, Qwen2.5-VL-3B, Qwen3-VL-4B and Qwen3-VL-8B with the same recipe. Test F1@.5 (in-distribution) [paper: 2603.13054 Table 2]:
   - 2B (InternVL) 42.0 | 3B 43.0 | 4B 45.2 | 8B 43.9. So 3B to 4B is +2.2, 4B to 8B is -1.3. The 4B is the top of the curve.
   - RL-only on 4B reaches F1@.3 5.8 and F1@.5 3.1 against 31.9 / 23.0 for SFT-only and 58.3 / 45.2 for SFT+RL. The format-gated reward collapses without SFT. [paper: 2603.13054 Table 4/5] This supports our SFT-first order.
4. Seg-R1 (2506.22624, GRPO prompts SAM2): 3B vs 7B on COD10K S-measure 0.857 vs 0.873 (+0.016 for 2.3x size). [paper: 2506.22624 Table 1] Not a 2B vs 4B point, but the same shape: a 2x size jump buys little after RL.
5. Moondream Segmentation (2604.02593): backbone is Moondream 3, 2B active / 9B total MoE; RL on the rasterised mask; cIoU 80.2 % on RefCOCO val. No size ablation. [paper: 2604.02593 sec 3] It shows that a 2B-active model reaches strong mask quality once RL scores the raster.
6. MedLoc-R1 (2603.28120, GRPO with a curriculum IoU threshold, medical boxes): backbones Qwen2.5-VL-3B and InternVL-2.5-4B, different families, so it is not a size test. After training HAM10000 A@0.5 is 93.96 (3B Qwen) vs 90.03 (4B InternVL); the 4B is lower. Untrained A@0.5 is 35.75 vs 33.19. [paper: 2603.28120 Table 8] The family and recipe mattered more than the 3B/4B size.
7. Direct 2B vs 4B for polygon output on medical images: no paper found. A search for it returned nothing that compared Qwen3-VL-2B and 4B under GRPO on medical grounding or segmentation. This is a real gap; our own run would be the first.

Measured gain from 2B to 4B, summary: +3 to +3.6 points on untrained grounding, shrinking to about +1.4 after SFT+RL (EGM); +2.2 to +3.2 F1@.5 in Topo-R1; about +0.02 in Seg-R1 3B to 7B. All are tasks where the failure is partly language understanding. [paper: above]

### B. Project data that bounds how much 4B can help
8. Capacity is not our binding limit. Images that the model finds score 0.722 against a doctor ceiling of 0.740. Misses (IoU<0.1) are 10.8 % of test images and come from RL on centred crops with a shifted test. [BRIEF sec 2; measured: runs/r5/eval/eval_test/final_eval.json shows test IoU 0.6448, 95 % CI 0.633 to 0.656, 2,200 images, K 8]
   The fix is data (shifted and rescaled train windows), already built. [code: experiments/phase2/configs/rl_shifted.yaml]
9. Upper bound on what any model can add: found images have 0.018 headroom; the rest of the headroom is misses, which are a data-coverage problem. A 4B model would need to find off-centre nodules the 2B model cannot see even after training on shifted windows. EGM's evidence (training closes the size gap) says it probably will not need to.

### C. Qwen3-VL-2B vs 4B: facts that set cost
10. Architecture from the HF configs [hf-api: Qwen/Qwen3-VL-2B-Instruct, Qwen/Qwen3-VL-4B-Instruct config.json]:
    - 2B text model: 28 layers, hidden 2048, 16 heads, 8 KV heads, MLP 6144. 4B: 36 layers, hidden 2560, 32 heads, 8 KV heads, MLP 9728.
    - Vision tower is identical: depth 24, width 1024 (only the output projection differs, 2048 vs 2560). So image encoding cost does not grow.
    - Total parameters: 2,127,532,032 vs 4,437,815,808 (2.09x). [hf-api: safetensors.total]
    - Non-embedding text parameters [computed from the config]: 2B 1.41 B, 4B 3.63 B (2.58x).
    - KV cache per token: 2B 112 KiB (this matches the repo comment) [code: experiments/phase2/hf_sample.py:15]; 4B 144 KiB [computed: 36 layers x 2 x 8 x 128 x 2 B] (1.29x).
11. The same tokenizer and the same 0-1000 grid: Qwen3-VL-4B is a drop-in for the 2B code path (same Qwen3VLForConditionalGeneration class). [hf-api: config architectures]

### D. Medical VLMs under 4B and whether medical pretraining helps polygon output
12. MedGemma-4B (and 1.5-4B) is Gemma3-based, 4.30 B parameters, gated, license "other" (Google HAI-DEF terms), not Apache. [hf-api: google/medgemma-4b-it, google/medgemma-1.5-4b-it]
    - Off the shelf it cannot localise: SLAKE grounding mean IoU 0.05 and Acc@0.5 0.0 %, below a fixed centre box (0.10). Lingshu-7B gets 0.07. [paper: 2604.27720 Table II]
    - MedGemma 1.5 added bounding-box localisation: chest ImaGenome IoU 3.1 to 38.0 (chest X-ray only, boxes only, no polygons, no CT localisation result found). [paper: 2604.05081, via search summary; the CXR number is from the report abstract area, not re-read from a table]
    - Different architecture from Qwen3-VL, so FastGRPO patches (shared-prefix, RopeCache, vision cache) written for Qwen3-VL would need a new port. [code: src/objdel/train/fast.py is Qwen3-VL-specific per BRIEF sec 1; I did not audit each patch]
13. Lingshu: only 7B (8.29 B) and 32B (33.45 B), Qwen2.5-VL based. HuatuoGPT-Vision: 7B (8.29 B) and 34B. Both exceed the owner's 4B limit and neither has grounding output. [search: Lingshu 2506.07044, HuatuoGPT-Vision table in 2510.10011; not re-read from the model cards]
    On grounding Lingshu-7B averages 13.9 IoU against 13.8 for general Qwen3VL-8B, so medical pretraining without localisation data gave no localisation gain. [paper: 2602.06965 Table 3]
14. MedMO-4B (MBZUAI/MedMO-4B and MedMO-4B-Next): Qwen3-VL-4B architecture with exactly 4,437,815,808 parameters, Apache-2.0, not gated. [hf-api: MBZUAI/MedMO-4B] This is the only sub-4B-limit medical model that drops into our stack.
    - Recipe: four stages, the last is RL with a box-IoU reward (Hungarian match). Medical grounding data was in the training mix.
    - MedMO-8B (Qwen3-VL-8B start) grounding IoU: DeepLesion 38.5 vs 0.0 for Qwen3VL-8B, Bacteria 54.6 vs 9.2, average 54.2 vs 13.8. [paper: 2602.06965 Table 3] The gain is from medical grounding data, not from "medical" as such.
    - The 4B grounding numbers are not in Table 3 (only 8B rows); MedMO-4B-Next does well on VQA (68.5) and QA (55.0).
    - The box RL stage added little on top of SFT: NIH +4.5, DeepLesion +0.4, Bacteria +0.4 IoU. [paper: 2602.06965 Table 4]
    - Output is boxes, not polygons. No polygon evidence.
15. Does medical init help after RL? The only matched test is RadVLM (2512.10691, 8B Qwen3-VL, CXR boxes): GRPO alone lifts general Qwen3-VL anatomy grounding from 11.1 to 79.0; the medical SFT model starts at 82.1 and reaches 84.5 with RL. So the medical start is worth about +5 box points after RL, with the general model already at 79.0. [paper: 2512.10691 Table grounding] The test is on boxes at 8B, not on 4B polygons.
    Our own SFT on 23,469 LIDC targets already does the domain adaptation. Topo-R1 keeps over 91 % of F1 with only 25 % of the SFT data, so data volume matters less than starting point once SFT exists. [paper: 2603.13054; BRIEF sec 2 for the 23,469]
16. Verdict on medical pretraining and polygons: no paper shows medical pretraining helps polygon text output. Evidence is for boxes only, and it says that localisation data in training, not the label "medical", is what helps. We have that data already (LIDC polygons).

### E. Cost model for a 4B arm (RTX 5090, about $0.60 per hour)
17. Baseline: the 2B shifted-views run is 300 steps at 23.6 s, about 2 h plus evals (about 18 min) plus checks: about 2.6 h, about $1.6. [code: experiments/phase2/configs/rl_shifted.yaml header; the $0.60 per hour is the plan's own rate]
    One 2,200 image, K=8 eval on 2B took 633 s. [measured: runs/r5/eval/eval_test/final_eval.json seconds.total 633.6]
18. 4B step time [estimate]: decode and training pass scale with the 2.58x text parameters; the vision tower and CPU phase (about 3 s) do not. Estimated 40 to 55 s per step against 23.6 s (about 1.7x to 2.3x). Mid-point 45 s.
    - 300 steps: 3.75 h. Two evals (val and test, about 2.2x of 10.5 min): about 0.8 h. Checks, load, save: about 0.3 h. Total about 4.9 h, about $2.9 at $0.60.
    - The owner's budget is $3 total for GPU scripts and the shifted 2B run alone takes $1.6. A full 4B arm does not fit with it.
    - A 4B arm also needs its own SFT (the 2B LoRA cannot be reused), whose cost I could not find in the repo. Not measured; unknown.
19. Memory [estimate, needs preflight]: 4B bf16 weights 8.9 GB [computed: 4.44 B x 2]. At vllm_gpu_memory_utilization 0.35 (11.2 GB) [code: src/objdel/train/configs.py:192] only about 2 GB is left for KV cache, which holds roughly 8 sequences of about 1.9 k tokens at 144 KiB per token. The value needs to rise to about 0.55 to 0.6. Colocated vLLM sleeps during the training pass, so the trainer has room. A 2B run holds about 6 GB of KV (11.2 minus 4.3 minus overhead), about 28 sequences by the same math.

## Recommendations

1. Decision: STAY on Qwen3-VL-2B for the B1 shifted-views run (rl_shifted.yaml). Change one variable at a time. The evidence says the miss problem is data coverage, and training closes most of the 2B-4B gap (EGM: +3.6 untrained to +1.4 trained).
2. Do NOT run 4B in parallel inside the $3 budget. A 4B arm costs about $2.9 for RL alone [estimate] plus an SFT whose cost is unknown. Both arms together exceed the budget.
3. Gate for a later 4B arm (decision record, ADR style): run 4B only if, after the shifted 2B run, test IoU_tc on shifted views is still below about 0.70 AND the miss rate (IoU<0.1) is still above about 6 %, i.e. the leftover is not explained by data. The gates are my suggestion, to be set by the owner before spend.
4. If the gate fires, use Qwen/Qwen3-VL-4B-Instruct as the base, not MedGemma, Lingshu or HuatuoGPT. Reasons: same architecture and 0-1000 grid (finding 11), Apache-2.0, FastGRPO patches work unchanged in principle, and the other three are either over 4B (Lingshu, Huatuo) or a different architecture with a gated license (MedGemma).
5. Only consider MBZUAI/MedMO-4B-Next as a second start point if the owner wants a medical-init test. It is a drop-in (finding 14), but there is no polygon evidence and the benefit after RL is about +5 box points at 8B (finding 15). Keep it as an SFT-start A/B only if budget allows: one SFT leg each.
6. Code changes for a 4B arm (do not do now):
   - src/objdel/train/configs.py:73-77: add `"qwen3-vl-4b": "Qwen/Qwen3-VL-4B-Instruct"` to MODELS, 1536 to MAX_COMPLETION, and the key to _LORA and _GRAD_CKPT.
   - src/objdel/train/configs.py:192: raise `vllm_gpu_memory_utilization` from 0.35 to about 0.55 for 4B, and re-measure with `make preflight`.
   - Hard-coded `qwen3-vl-2b` defaults: experiments/phase2/final_eval.py:53, train_rl.py header, profile.py:53. Pass `--model qwen3-vl-4b`.
   - New config experiments/phase2/configs/r6_qwen3vl4b.yaml with `model: qwen3-vl-4b`; reference file vision_ref/qwen3-vl-4b.json (written by the R0 vision reference step).
   - Measure first: a 15-step speed probe (like r4_speed.yaml) to replace my 40 to 55 s estimate. Cost is about $0.25 [estimate: 15 steps x 45 s + load, about 0.4 h x $0.60].
7. A cheaper way to learn whether size matters: from the existing 2B run, compare IoU on the found images (0.722 vs ceiling 0.740). If found-image IoU is already within 0.02 of the ceiling, a bigger model cannot gain there. Zero cost, from existing outputs.
8. Papers worth copying regardless of size: EGM's learnability filter (RL data sized per model, 111 k samples for 2B, 79 k for 4B, 84 k for 8B) [paper: 2601.13633 Table 7]; MedLoc-R1's curriculum IoU threshold for sparse early reward; SimpleSeg's no hard-length-penalty rule (hard penalty drops gIoU from 76.9 to 66.7) [paper: 2601.19228]. These feed B3 (reward v5), not the model choice.

## Open questions
1. SFT cost for a 4B arm is unknown: I found no SFT hours or dollars in the repo notes I searched (changelog, ROADMAP, research notes). Needs the R1 timing from the owner or a measured probe.
2. No paper compares Qwen3-VL-2B and 4B on polygon text output for medical images. Our result would be the first. The 2B to 4B gain on that task is therefore an extrapolation from grounding and topology tasks.
3. MedMO-4B grounding numbers: only the 8B rows are in Table 3. Check the MedMO model card or code repo for 4B grounding before any use.
4. MedGemma 1.5 CT localisation: the report snippet I saw gives only chest X-ray localisation. I did not read the full PDF table for CT. This matters little since MedGemma is excluded for architecture and license reasons.
5. Whether 4B at 0.55-0.6 vLLM memory share leaves enough room for the 16x16 micro-batches and the 1.61 GB pixel_values buffer: untested; needs preflight.
6. Whether the 4B step time scales as I estimated (1.7x to 2.3x). Needs the 15-step probe in Recommendation 6.
7. Qwen3.5-4B (hybrid Gated-DeltaNet, RefCOCO-avg 88.1) is a different architecture and breaks Qwen3-VL-specific patches per docs/implementation2.0/notes/E_vlm_seg_sota.md; I did not re-verify that claim.
