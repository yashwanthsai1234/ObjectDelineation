## Findings

### F1. Our data state (verified)
- Plan: 24,624 rows = 8,208 centred + 8,208 shifted + 8,208 rescaled; disagreement items x4 inside each block [code: experiments/phase2/configs/rl_shifted.yaml header; src/objdel/train/dataset.py DISAGREEMENT_OVERSAMPLE = 4].
- 300 steps x 32 prompts = 9,600 prompts = 0.39 of one epoch [code: rl_shifted.yaml header; train_rl.py docstring "32 LIDC train prompts per step"]. So at most 39 % of rows are ever seen: WHICH 9,600 are drawn is the whole data decision.
- Sampler: TRL RepeatSampler permutes uniformly, no weights [code: dataset.py:29-30]; `RepeatSampler(shuffle: bool=True, seed)` exists in TRL 1.17.1 [code: .venv trl/trainer/utils.py ~867]. TRL 1.17.1 GRPOConfig has no dynamic-sampling / filter option [code: grep of trl/trainer/grpo_config.py: only `scale_rewards`]. It already logs `frac_reward_zero_std` [code: trl/trainer/grpo_trainer.py:2949].
- Centred rows are saturated: train IoU_tc 0.77 vs doctor ceiling ~0.73; centred test items 0.77 [measured: docs/research/notes/rl_plateau_diagnosis_2026-11-08.md].
- Test is shifted: object offset median 0.265, 37.5 % > 0.3. Test IoU by offset: <0.15 0.76-0.77; 0.15-0.2 0.710; 0.2-0.3 0.670 (5.9 % miss); >0.3 0.545 (23.0 % miss). Off-centre >0.3: size 0-40 px 0.326 (47 % miss), 40-80 px 0.496 (30 %), >80 px 0.619 (14 %) [measured: same note].
- Train windows already match the test shift: shifted median 0.247 / 65.9 % > 0.2; rescaled 0.312 / 76.6 % > 0.2; test 0.265 / 69.9 % [measured: same note].
- Zero-spread groups in the old run: 0.0 % (steps 1-100) to 2.7 % (751-770) [measured: same note]. Reward is continuous (IoU), so exact zero variance is rare; the real risk is groups where all 8 answers MISS (reward ~0, tiny spread) on small off-centre objects. Not measured.
- Leakage: LIDC split is already patient-level, 70/10/20, two-scan patients kept together [code: src/objdel/data/splits.py:3]. Windows are cut only from train items, with "union inside, 2 px clearance, no other outlined nodule" [code: experiments/phase2/build_eval_views.py docstring l.11-12]. Windows are built with fixed-seed per-item RNG (augment.row_rng) [same file l.19].

### F2. External evidence
1. Augmentation vs test-distribution matching.
   - Our diagnosis is the standard "train/eval view mismatch" case; fixing it is first-order. In the polygon-RL literature the RL stage uses the SFT distribution: SimpleSeg RL refines SFT point sequences on referring-seg data with an IoU reward [paper: arXiv 2601.19228]; it does not publish an RL data recipe (abstract/README only; the RL dataset, size and filtering are not stated in what I could fetch) - so there is no published number to copy.
   - Moondream Segmentation: SFT on >10M images, then GRPO with a piecewise reward (box IoU while mean box IoU < tau_box -> Tversky (beta>alpha, punishes false negatives) -> boundary IoU, eps = 5 % of diagonal); invalid paths reward 0 and are excluded from group means; no augmentation, group size or RL data size stated [paper: arXiv 2604.02593; Moondream blog 2026-03-10]. Lesson for us: the "curriculum" is on the REWARD, not the data order. That belongs to B3.
   - NoisyRollout: mixes rollouts from clean and distorted images in ONE group, updates only on the clean input; distortion annealed to zero; helps at 1.1K-6.4K samples [paper: arXiv 2504.13055]. Different from ours (our windows change the label geometry and are re-scored on their own masks, which is correct), but supports "augmented views early, taper later" and small-data gains.
   - Syn-GRPO: synthesises new images by outpainting background around a kept foreground so the box label stays valid; stresses label preservation and small shift from the old distribution [paper: arXiv 2511.19343]. Relevant only as a label-validity principle (see F2.5).
2. Curriculum and hard-example sampling.
   - MedLoc-R1 (CVPR 2026): fixed IoU reward gives reward sparsity on small/ambiguous medical regions; a sliding-window tracker raises the IoU threshold only when mean reward >= P, reward std <= S and IoU margin >= 0.10; data split is plain random 8:2, no data curriculum; tested on HAM10000, HEEL, TN3K; group-size grid G=4/6/8/10 on HAM10k: 89.10 / 93.51 / 94.46 / 94.36 [paper: arXiv 2603.28120 and CVPR 2026 supplemental]. Note: its 8:2 split is random (not patient-aware) - do not copy that.
   - CuRPO (visual grounding): more data can HURT; sort examples by CoT length and reward-based difficulty, easy-to-hard [paper: arXiv 2511.13924].
   - Curriculum-guided GRPO for driving detection: difficulty = consistency across stochastic detections of a base model; easiest ~40 % first, then shift 60 -> 80 % toward hard CODA; 58.9 IoU CODA / 78.4 BDD at 5K steps [paper: arXiv 2509.22688].
   - Bae et al. 2026 (GSM8K, 3 seeds): fixed medium-difficulty band 0.6449 +- 0.0024; moderately harder band 0.6591 +- 0.0077; hardest band 0.6405 +- 0.0053: the benefit is non-monotonic, re-estimate difficulty under the current policy [paper: arXiv 2610.13669]. Single small task, text only: weak evidence for vision.
   - Aperture (probe prior): pass rate is a weak forecast of future zero-variance; score every prompt with base + a short probe model, weight prompts by predicted probability the group splits; works alone or with dynamic sampling; 1.7B and 4B models [paper: arXiv 2610.25325]. This is the cheapest published fit to a 0.4-epoch budget.
3. Zero-variance groups.
   - DAPO dynamic sampling: over-sample, drop groups with accuracy 0 or 1, refill the batch; same performance reached faster; generation cost rises but the long tail dominates a synchronous system anyway [paper: arXiv 2503.14476]. NeMo-RL exposes it as `use_dynamic_sampling`, `batch_multiplier`, `dynamic_sampling_max_gen_batches` [NVIDIA NeMo-RL DAPO guide].
   - Silent-group probability = p^G + (1-p)^G; at G=8 and p=0.9 -> 0.43 + 0 = 43 %; at p=0.5 -> 0.8 % [paper: arXiv 2607.00152, eq. 10; numbers are my arithmetic on that formula]. This is for binary rewards; ours is continuous, so use a spread threshold, not "all equal".
   - AI21 dynamic difficulty filtering / snoozing: drop all-1 groups from later epochs; ~3x compute efficiency on GSM8K, same 84 % final score; permanently dropped easy items drift in multi-dataset mixes, so "snooze" 2-5 epochs instead [AI21 blog 2026-01-22].
   - Dynamic sampling over-amplifies wrong answers on hard prompts [paper: arXiv 2608.27982] - another reason not to drop hard rows outright.
   - For us: Dr. GRPO (no std division) is already used, so zero-spread groups give ~zero gradient (only KL beta 1e-3). Their cost is generation time, not harm.
4. Leakage and quality gates in LIDC.
   - Random image-wise splits leak patient identity and inflate scores; patient-wise splits are needed [paper: PMC11408573, Ashames et al. 2024]; same mechanism shown in pathology [medRxiv 10.1101/2020.04.23.20076406]. Adjacent-slice similarity motivates patient-level splits [paper: arXiv 2512.00748, cited in splits.py]; slice-level splits inflate CT segmentation [arXiv 2604.15561, cited in splits.py].
   - LIDC curation varies widely between papers (slice thickness, >=3 readers, aggregation); publish the exact ID list [paper: arXiv 2108.05386]. Our `item_id` + manifest SHA-256 already does this.
   - Standard split tools use StratifiedGroupKFold by patient [DeepWiki mueller-franzes/MST]; ours is a seeded hash-deal, equivalent in effect.
5. Synthetic hard cases.
   - Safe for label-preserving geometry (shift, rescale of the same CT slice, re-scored on the window's own rater masks) - what we do. Outpainting/generative synthesis changes CT texture and can invalidate nodule boundaries (Syn-GRPO keeps the foreground fixed for this reason). No evidence found that generative CT synthesis helps RL grounding of nodules; do not use it before B1 is done. [estimate / absence of evidence]

## Recommendations

R1. Draw the 9,600 prompts by an explicit weighted plan, not uniform. Implement `dataset.schedule_rows(rows, steps, per_step, weights, seed)` in src/objdel/train/dataset.py returning a Dataset in step order; pass it to the trainer with `RepeatSampler(shuffle=False)` by overriding `_get_train_sampler` in the FastGRPO subclass (src/objdel/train/fast.py). Test in tests/test_p2_views.py (counts per kind, no item twice in a step, determinism by seed). Keep `--train-views` as is.
R2. Window-kind shares of the 9,600 [estimate]: centred 15 % (1,440), shifted 55 % (5,280), rescaled 30 % (2,880). Why: centred is saturated (0.77 vs ceiling 0.73) - keep a minority as a regression anchor; test uses shifted only; rescaled is harder (median offset 0.312) and gives scale robustness. Config key: new `--kind-shares 0.15 0.55 0.30` in experiments/phase2/train_rl.py.
R3. Within shifted and rescaled, tilt by object offset bin (from row["view"]["offset"] / side, already stored): weight 1.0 for offset <0.2, 1.5 for 0.2-0.3, 2.0 for >0.3 [estimate]. On the shifted block this lifts the >0.3 share from ~37.5 % (test-like) to ~48 % (arithmetic on the test shares; 0.2-0.3 share assumed ~30 %). Extra x1.5 for objects <40 px at offset >0.3 (47 % test misses). Keep the tilt mild: Bae et al. show harder-than-needed bands lose accuracy (0.6405 vs 0.6591). Draw without replacement, so no row repeats beyond its disagreement x4 copies.
R4. One window per source item per step: when building a step's 32 prompts take 32 distinct item ids (the three windows of one CT slice are strongly correlated; a step with 3 copies wastes signal). Add this as a property test.
R5. Per-epoch/stage schedule for the 300-step run (one pass over a 0.39-epoch draw): steps 1-100 shares 25/50/25 (more centred for stability after the model sees new window kinds), steps 101-300 shares 10/58/32. This is a cheap MedLoc-style "ease in", but evidence is weak (MedLoc schedules the reward, not the data); apply only if R7's probe shows >15 % zero-spread groups in the first 20 steps; otherwise use R2 flat. If a second run follows, restart the draw with a new seed over rows not yet used (record used keys in <out>/rl.json "log").
R6. Offline probe before spend (preflight, ~$0.25 [estimate: 2,048 prompts / 32 = 64 step-equivalents x 23.6 s = 25 min at $0.60/h upper bound; generation only is cheaper]). New script experiments/phase2/probe_rows.py: run the final checkpoint with G=8 on a stratified 2,048-row sample (kind x offset bin x size bin), write per-row group mean IoU, std, miss-rate. Output table p(all-miss), p(all-solved), p(split) per bin. Use it to (a) fit R3 weights to the measured p(split) (Aperture-style [arXiv 2610.25325], simplified to one probe model), (b) drop rows predicted saturated: group mean >0.85 and sd <0.03 [estimate thresholds, tune on the probe]. Do NOT drop all-miss bins: those are the target; send them to the reward fix (B3, location term).
R7. In-run guards, no new trainer code: log `frac_reward_zero_std` (already in TRL) and per-kind/per-offset mean reward each step via a callback in src/objdel/train/callbacks.py. Abort/notify rule [estimate]: zero-spread share >25 % over 20 steps => stop the run and revisit R6 weights or the reward. Do not implement DAPO dynamic sampling in FastGRPO now: shared-prefix + vLLM sleep make a refill loop costly; with a continuous reward and 0-2.7 % measured zero-spread it is not the bottleneck. Revisit only if shifted rows show >25 %.
R8. Leakage / quality gates in the build (extend experiments/phase2/build_eval_views.py manifest and add tests/test_data_gates.py); fail the build on any breach:
  - G1 patient disjoint: set(group_id of train windows) ∩ set(group_id of val/test items) = ∅ (group_id = patient [code: lidc.py:316]); also the 8 two-scan patients.
  - G2 windows only from `split == train` records; assert manifest `split` field.
  - G3 pixel-hash check: no train window SHA-256 equal to any val/test image SHA-256 (dataset.py records `image_sha256`).
  - G4 label validity per window: target mask non-empty, entirely inside the window with >=2 px clearance, no other outlined nodule inside (already in augment.draw; assert it again on the written records), polygon needs <= 1,200 tokens (the count above 1,200 is unknown; A phase counts it).
  - G5 fallback/kept_side share: report share of rows that fell back to the centred frame or kept the side; fail if rescaled `kept_side` > 30 % (the plan's own limit, build_eval_views docstring l.14-15).
  - G6 report-only coverage table: rows per (kind x offset bin x size bin x rater count x disagreement); flag empty bins. This is the owner's "audit coverage before spend".
R9. Do not use generative or outpainted synthetic CT, and do not add image noise rollouts now. Order: fix the view mismatch (R1-R3), measure (R6-R7), then consider NoisyRollout-style annealed distortion (arXiv 2504.13055) as a later experiment on the same 24,624 rows.
R10. Keep disagreement x4. It is already inside the 8,208 per block; check its share of the 9,600 draw in the coverage table (expected ~?: not measured) and keep it <= 25 % [estimate] so doctor-disagreement slices do not dominate.
R11. Acceptance for the recipe (A phase metrics): report test IoU_tc by offset bin and miss rate (>0.3 offset, <40 px). Success target [estimate]: >0.3-offset mean 0.545 -> >=0.60 and overall miss rate 10.8 % -> <=8 %, with centred bins not dropping by more than 0.01.

## Open questions
1. What is the measured per-row miss and spread on the train windows (R6 closes this)? Weights in R2/R3 are guesses until then.
2. How many of the 8,208 are disagreement x4 repeats, and what is the distinct-item count? (needed for R4/R10; read data/prepared manifest with `python -I`.)
3. Will the rescaled block help the shifted-only test? SFT used it; no RL ablation exists. A 100-step A/B (R2 15/55/30 vs 15/85/0) would cost ~$0.7 [estimate: 100 x 23.6 s = 39 min at $0.60/h]; the $3 budget allows one.
4. Does a data curriculum matter at 0.39 epoch, or is the reward (B3) the better lever? MedLoc's evidence is for the reward schedule.
5. TRL private-name risk: overriding `_get_train_sampler` touches a private method of TRL 1.17.1; confirm it exists in the pinned version at start-up (A-phase check) and fall back to a pre-shuffled dataset plus `shuffle=False` through GRPOConfig-free subclassing.
