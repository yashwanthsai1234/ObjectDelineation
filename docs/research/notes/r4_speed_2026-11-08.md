Findings:
- **Same learning, faster.** Step 1 is identical to the full run's (legal 0.9297, IoU 0.565) and steps 3-15 match to
  three decimals, so the no-merge sync and the 64-wide chunks change speed only. The vLLM-vs-trainer token logprob
  gap is 0.011 nats (full run 0.016).
- **8 % faster per step** (32.66 -> 29.94 s at the same answer lengths), nearly all in the update (14.73 -> 12.46 s):
  narrower chunks. Caveat: a different host than the full run (same card type).
- **vLLM sleep mode is not the bottleneck.** The handovers cost 1.6 s per step in total (sync 1.28, wake 0.12,
  sleep 0.25); keeping vLLM awake saved 0.05 s per step (within noise). Sleep mode stays on: it frees memory. The
  67-73 % GPU use comes from inside the generate and batch phases (CPU-side image processing and scheduling, the
  8x repeated prompt), not from the handovers; `rl_code_optimality_review_2026-11-08.md` #1 (shared-prefix forward)
  is the next lever.
